## Milestone 1 — Bridge Core (local) 🎯 next

**Goal:** Build the reusable **Bridge core** (`bridge/`, currently only the S0.2 scaffold) as an independent project with **in-memory / local seam adapters only** — the real Bridge behind the same A2A contract the mock already doubles, so the **mock→real swap is a no-op for the agent** (`agents/` unchanged). This is the Sprint-1 "real Bridge (local)" body: aggregate model, both edges, dual-path fulfillment, the fixture extraction graph, deterministic disposition + classification + issuer canonicalization, the classified ledger, and proactive follow-up on a virtual clock. Design roots: [`wiki/bridge.md`](wiki/bridge.md) and the ADRs cited per task.

**Governing invariants (honor throughout):** `bridge/` **never imports** `agents/` (guarded by `bridge/tests/test_no_agents_import.py`); **LLM routes, code decides** — `run_disposition_gate` and completeness are deterministic pure functions, a model may never mint a KYC acceptance (lessons A3); **mock↔real parity is terminal-outcome, not ledger-identical** (same terminal reason + accepted-issuer set — lessons A2); the **classified ledger has no timestamp** so any store adapter needs a deterministic sort key (lessons A5); **`resubmit` is non-resumable**, escalation ≠ rejection (lessons A1); **trust boundary is permissive-by-default** (per-party scoping only under `strict=True` — lessons A6).

**Out of scope (Sprint 2 GCP / later phases):** all GCP adapters + Terraform; real Gemini extraction (local uses the **fixture** engine; Gemini is Sprint 2, Document AI is Phase 4); push-notification webhooks (Phase 3 — interim is `tasks/get`/`resubscribe`, ADR-0008); Bridge-as-client / outbound / real party-channel sends (Phase 4 — Phase 1 is inbound-only); Benefits (Phase 2); RFP / emergent Collect / live skill-add / showcase runner (Phase 3); multi-tenancy, party memory, cold-inbound Extract edge, four-signal disposition, B→A migration, hardening (Phase 4).
