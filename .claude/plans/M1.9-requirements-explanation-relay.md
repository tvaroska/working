# M1.9 — Requirements + best-effort completeness + explanation relay

**Milestone:** M1 (Bridge Core, local) · **Depends on:** M1.8 (A2A inbound edge), M1.4 (ledger), M1.6 (disposition), M1.3 (skill registry) · **Parity anchor:** `agents/src/agents/address/satisfaction.py::is_satisfied`

## 1. Goal (what "done" means)

Give the real Bridge three capabilities on the inbound A2A edge:

1. **Best-effort advisory completeness** — a pure, Bridge-side function that reads the classified ledger and applies the Address **prose** satisfaction rule (one accepted `gov-id` **OR** ≥2 accepted `utility-bill`s from **distinct canonical issuers**) to propose *what is still outstanding*. It is **advisory only**: the app (the `RemoteA2aAgent` consumer) still owns the final `done`. It must be **terminal-outcome-parity** with `agents`' `is_satisfied` (same `done` verdict + same accepted-issuer set), never ledger-identical (lessons **A2**).
2. **Emit the app-owned `RequirementsList`** artifact (already defined in `contract`), carrying per-item `reason_code` + `message`.
3. **Relay per-doc `reason_code` + `message`** on rejected `LedgerEntry`s, **verbatim** — the Bridge transports the domain prose; it never authors or edits it (ADR-0013).

### Non-goals (do NOT do here)
- **No A2UI content mapping** — turning `{status, message, doctype_hint}` into declarative render blocks is **M1.10**. M1.9 only produces the *data* on the wire.
- **No chase/scheduler** — "chase the delta" mechanics are **M1.12**. Here, "chase" only means *computing* the outstanding delta from the real rule.
- **No change to the consumer's loop gate** — `agents/.../graph.py` keeps driving `is_satisfied` off `CollectionStatus.ledger`. The `RequirementsList` is *for the party*, not the consumer loop.
- **No dual-path intake** (M1.11). Documents still arrive via the `CollectPlan` fixture stand-in.

## 2. Key design decisions & gotchas (read before coding)

- **Parity by discipline, not by import** — `bridge/` MUST NEVER import `agents/` (guard: `bridge/tests/test_no_agents_import.py`). So we **re-implement** the rule fresh in `bridge/` (exactly as M1.5 did for canonicalization). Mirror the constants from `satisfaction.py` (`GOV_ID`, `UTILITY_BILL`, `REQUIRED_DISTINCT_ISSUERS=2`) and the exact semantics: only `ACCEPTED` counts; bills with empty/None issuer are excluded from the distinct count; issuer is already canonical (do not re-canonicalize).
- **Where the prose lives (ADR-0013 fidelity):** the Bridge must stay domain-agnostic and **relay** skill/app-authored prose. Store the message templates + requirement labels in a **skill asset**: `skills/address-proof/assets/explanations.yaml`. The Bridge *reads* it and relays verbatim; it authors no prose. The **code** (this module) decides *which* `reason_code` applies (that is the "code decides" half of A3); the **data** (yaml) supplies the human `message` (the "LLM/app authors" half).
- **No message interpolation** — keep `message` strings static so "verbatim relay" is literal (no `{issuer}` substitution by the Bridge). Write the distinct-issuer message generically ("...send a second bill from a different provider...").
- **`reason_code` is a free string, per-skill** (ADR-0013 §2/§54) — do not add a global enum to `contract`. Define the code constants locally in the new bridge module.
- **Wire emission — minimal breakage (IMPORTANT):** emit the `RequirementsList` as a **second `DataPart` inside the same single artifact** as the `ExchangeTurn`, with the **`ExchangeTurn` part first** (`parts=[exchange_turn_part, requirements_part]`). This is critical:
  - `contract.ExchangeTurn` and `contract.RequirementsList` are distinct top-level shapes (`ExchangeTurn` has `context_id`+`status`; `RequirementsList` has `requirements`+`done`). ADR-0013 §3 requires the `RequirementsList` travel *alongside* `ExchangeTurn`, **not nested** in `CollectionStatus`.
  - Because `get_data_parts(...)` preserves order, `datas[0]` stays the `ExchangeTurn` → **existing M1.8 decoders keep working unchanged**: `bridge_client/wire.py::task_to_exchange_turn` (`datas[0]`), `test_edge_a2a.py::_turn_from_task` (`artifacts[-1]`→`datas[0]`), and `wire.extract_exchange_turn` (already filters by `status.ledger` presence, so it naturally skips the `RequirementsList` part). **Verify this holds; do not reorder.**
  - Add a new decoder `requirements_from_task(task)` to `bridge_client/wire.py` that selects the part whose dict has a top-level `requirements` key (shape-based, not index-based) — for M1.10's use and the round-trip test.
- **Terminal flag stays plan-driven** — do **not** rewire `terminal`/park-vs-complete off the advisory. `CollectPlan.round_for(r).terminal` still scripts when the exchange ends and still drives `_overall_disposition(... terminal=...)`. Rewiring `terminal` to the advisory `done` risks perturbing M1.8's park/resume tests and collides with `_overall_disposition`'s PENDING-leg handling. The advisory only replaces the **`outstanding`** source (see below). Note this scope boundary in a code comment.
- **`outstanding` now comes from the real rule**, not `CollectPlan.outstanding`. Remove the `outstanding` field from `CollectRound` and the `.outstanding()` method on `CollectPlan` (M1.9 now owns it); update the three plan literals in `plan.py`. Grep confirms `.outstanding` on plans is only used in `executor.py` and referenced in `plan.py` — no test reads it.
- **Keep the new module out of `bridge/__init__.py`** (same rule `ledger.py`/`disposition.py`/`aggregate.py` follow — preserve cheap `import bridge` + no-agents-guard clarity).
- **Import discipline for the new module:** `contract` + `bridge.{disposition}` + stdlib/pydantic/yaml only. Never `agents`, never `seams`/`adapters`.

## 3. Files to create / modify

### CREATE `skills/address-proof/assets/explanations.yaml`
The app/skill-authored domain prose the Bridge relays verbatim. Shape:
```yaml
# Per-item requirement templates (the app-owned "what's needed" labels).
requirement:
  item: "proof of address"
  doctype_hint: gov-id
# reason_code -> human message. Bridge relays these VERBATIM (ADR-0013). Static strings only.
reasons:
  proof-required: "Send a government-issued photo ID, or two utility bills from two different providers."
  distinct-issuer-needed: "We have one utility bill on file. Send a second bill from a different provider, or a government-issued photo ID."
  unsupported-doctype: "That document is not an accepted proof of address for this program. Send a driver's licence / state ID, or a utility bill."
  illegible: "This document was too blurry to read. Please resend a clearer copy."
```

### CREATE `bridge/src/bridge/requirements.py`
Pure, deterministic. Public API (`__all__`):
- **Constants:** `GOV_ID="gov-id"`, `UTILITY_BILL="utility-bill"`, `REQUIRED_DISTINCT_ISSUERS=2`; reason-code constants `PROOF_REQUIRED="proof-required"`, `DISTINCT_ISSUER_NEEDED="distinct-issuer-needed"`, `UNSUPPORTED_DOCTYPE="unsupported-doctype"`, `ILLEGIBLE="illegible"`.
- **`class SkillExplanations(BaseModel, frozen=True)`** — `item: str`, `doctype_hint: str | None`, `reasons: dict[str, str]`. Method `message_for(reason_code) -> str | None`.
- **`load_explanations(skill: Skill) -> SkillExplanations`** — read `skill.asset_path(skill.metadata.get("bridge-explanations", "assets/explanations.yaml"))` with `yaml.safe_load`; tolerate a missing file by returning an empty-reasons `SkillExplanations` (so `message` fields degrade to `None` rather than crashing). (Keeps the Skill model + `load_skill` untouched — no M1.3 change needed.)
- **`class AdvisoryResult(BaseModel, frozen=True)`** — `done: bool`, `outstanding: list[str]`, `accepted_issuers: list[str]`. Field-for-field mirror of `agents`' `SatisfactionResult` (parity by discipline; note this in the docstring).
- **`advisory_satisfaction(status: CollectionStatus) -> AdvisoryResult`** — the re-implemented rule. Copy the exact logic of `is_satisfied` (accepted-only filter; `gov_id_ok = any accepted gov-id`; `bill_issuers = sorted(distinct non-empty issuers of accepted bills)`; `done = gov_id_ok or len(bill_issuers) >= 2`; `outstanding = [] if done else [GOV_ID, UTILITY_BILL]`; `accepted_issuers = bill_issuers`).
- **`propose_requirements(status: CollectionStatus, *, explanations: SkillExplanations) -> RequirementsList`** — build the app-owned artifact:
  - Compute `advisory_satisfaction(status)`.
  - If `done`: one `Requirement(item=explanations.item, status=SATISFIED, doctype_hint=explanations.doctype_hint, reason_code=None, message=None)`; `RequirementsList(requirements=[...], done=True)`.
  - If not done: pick the `reason_code`: `DISTINCT_ISSUER_NEEDED` when there is **exactly one** distinct accepted bill issuer and no accepted gov-id (i.e. `len(accepted_issuers)==1`), else `PROOF_REQUIRED`. Build one `Requirement(item, status=REQUIRED, doctype_hint, reason_code, message=explanations.message_for(reason_code))`; `done=False`.
- **`explain_rejection(entry: LedgerEntry, gate: Gate, *, explanations) -> tuple[str | None, str | None]`** — for a **rejected** entry only: `Gate.UNSUPPORTED -> (UNSUPPORTED_DOCTYPE, msg)`; `Gate.RESUBMIT -> (ILLEGIBLE, msg)`; anything else / non-rejected `-> (None, None)`. (Accepted + pending docs carry no explanation.)

## 4. Tests to add

### CREATE `bridge/tests/test_requirements.py`
- **Parity suite (the acceptance anchor):** load `wiki/evals/address/expected.json` (copy the `_entries(*ids)` helper from `agents/tests/test_satisfaction.py`, building `LedgerEntry` explicitly — raw has extra keys). Assert `advisory_satisfaction(...)` returns the **same** `done`, `outstanding`, and `accepted_issuers` as `is_satisfied` for every scenario in `test_satisfaction.py`: `gov-id-clean` (done); `gov-id-expired` (not done); two power-co bills (not done, 1 issuer); `bill-powerco-clean`+`bill-aquautil-clean` (done, 2 issuers); powerco+pending aquautil (not done); powerco+rejected aquautil (not done); gov-id+rejected bill (done); passport-unsupported (not done); empty (not done); full corpus (done). ## 5. Acceptance criteria (all must hold)
1. `advisory_satisfaction` produces **terminal-outcome parity** with `agents`' `is_satisfied` (`done` + `accepted_issuers` + `outstanding`) across **every** `expected.json` scenario — asserted in `test_requirements.py`.
2. The edge emits the app-owned `RequirementsList` **alongside** the `ExchangeTurn` (second data part, same artifact), with per-item `reason_code`+`message` sourced **verbatim** from `skills/address-proof/assets/explanations.yaml` (Bridge authors/edits nothing).
3. Rejected `LedgerEntry`s carry `reason_code`+`message` (verbatim); accepted/pending carry `None`/`None`.
4. `CollectionStatus.outstanding` on the wire is computed from the real rule (not the retired `CollectPlan.outstanding`).
5. All existing M1.8 edge tests + the no-agents-import guard stay green; `bridge/` and `agents/` suites both pass: `uv run pytest` (from each package; fall back to `.venv/bin/pytest`). Run `ruff` clean.
6. `bridge/requirements.py` imports only `contract` + `bridge.{disposition}` + stdlib/pydantic/yaml; it is **not** re-exported from `bridge/__init__.py`.
