# M1.1 — Seam interfaces (all six)

**Milestone:** 1 (Bridge Core, local) · **Task line:** `PLAN.md` M1.1 · **Depends on:** M1.0 (shared `contract` package move — done). **Foundation for:** M1.2, M1.3, M1.4, M1.6, M1.7, M1.8, M1.12 (everything below in Milestone 1).
**Governing refs:** `wiki/bridge-seams.md` (seam table + "one shared suite, two adapters"), ADR-0003 (exchange view-vs-record), ADR-0004 (signal contract — *downstream*, not built here), ADR-0005 (extraction engine binding), `docs/lessons-learned.md` A5 (deterministic sort key), A7 (scheduler exactly-once), A13 (session/task restore is platform-default), C3 (env-var seam-mode contract). Prior art: `.claude/plans/S0.3-seam-test-harness.md` (the harness this task grows).

## Goal (scope of THIS task only)

Two deliverables, nothing more:

1. **Define the six seam interfaces** as `@runtime_checkable` `typing.Protocol`s, one module per seam, under `bridge/src/bridge/seams/`. These are *contracts only* — method surfaces grounded in the ADRs/contract types, no behavior.
2. **Grow the S0.3 `adapter` fixture** (`bridge/tests/support/seams.py`) from yielding a mode *string* to yielding a built **local adapter instance** for the seam under test, via a small production-side local factory. GCP adapters remain deferred to Sprint 2 (the `gcp` param keeps skipping).

To make the fixture able to *build* a local instance per seam, this task also creates **minimal local-adapter skeletons** for the four Bridge-invented/capability seams (exchange store, skill registry, scheduler, extraction). Sessions and Task store reuse the **native platform classes** directly (no skeleton). The skeletons are constructible and satisfy their Protocol structurally; their methods raise `NotImplementedError` — **M1.2/M1.3/M1.7/M1.12 fill in the real behavior.**

### Explicitly NOT in this task
- **No real adapter behavior.** No in-memory store logic, no skill-folder loading, no virtual-clock timers, no extraction. Skeleton methods raise `NotImplementedError`; real bodies land in the dependent tasks (M1.2 stores, M1.3 skill registry, M1.7 fixture extraction, M1.12 scheduler).
- **No GCP adapters** (Sprint 2). The `gcp` fixture branch skips.
- **No `SignalProvider` / `DispositionSignals`** (ADR-0004) — that is M1.6. The extraction seam here returns the existing `contract.Extraction`; do not invent the four-signal model now.
- **No config-driven seam selection from env vars** (C3 `BRIDGE_SEAM_*`). The factory dispatches on the `Seam` enum only; wiring env-var selection is deferred (M1.2+/deploy). Leave a one-line comment noting C3 is the future selector.
- **No new contract models.** Reuse `contract` types (`Extraction`, `CollectRequest`, `ExchangeTurn`, etc.). Where a seam needs a shape that doesn't exist yet (an exchange record, a skill object, a timer), use `typing.Any`/`object` in the signature and leave a `# M1.x defines the concrete type` note — do not pre-invent aggregates the dependent task owns.

## Context an executor needs (do not re-derive)

- **Three peer uv projects**; run all commands from **inside `bridge/`**. `bridge/` depends on `google-adk>=2.7.0,<3`, `a2a-sdk[http-server]`, `pydantic>=2`, and the shared `contract` package (all already in `bridge/pyproject.toml`).
- **Native classes are verified importable in `bridge/`'s venv** (checked during planning):
  - `from google.adk.sessions import BaseSessionService, InMemorySessionService, VertexAiSessionService` — `BaseSessionService` methods: `create_session, get_session, delete_session, list_sessions, append_event, get_user_state, flush`.
  - `from a2a.server.tasks import TaskStore, InMemoryTaskStore` — `TaskStore` (ABC) methods: `save, get, delete, list`.
  These are the local (and, later, GCP) adapters for Sessions and Task store — **prefer the platform-native construct** (CLAUDE.md / ADR-0001). Our Protocols mirror their method *names* so the native classes conform with zero glue.
- **`@runtime_checkable` caveat (important):** `isinstance(x, Proto)` for a runtime-checkable Protocol checks **method presence only, not signatures**. That is exactly what we want for M1.1 conformance smoke tests (real behavior/signatures are pinned by the shared suite in M1.2+). Keep every Protocol **method-only** (no data attributes) or `isinstance` will raise/misbehave. State this caveat in each module docstring.
- **The `adapter` fixture today** (`bridge/tests/support/seams.py`): parametrized `params=("local","gcp")`, returns the mode string; `gcp` skips unless `BRIDGE_TEST_GCP=1`. Re-exported by `bridge/tests/conftest.py`. The `@pytest.mark.seam("<name>")` marker + a collection-time validity guard already exist (`conftest.py`). Six seam keys: `sessions, task_store, exchange_store, skill_registry, scheduler, extraction` (`bridge/src/bridge/seams/__init__.py` `Seam` enum — the single source of truth).
- **Extraction is the CAPABILITY axis, not local↔gcp** (`wiki/bridge-seams.md` §"Axis nuance", C3, ADR-0005): engines are `fixture|gemini|docai`, selected by config + per-doctype capability, deployed either way. So for the `extraction` seam the `local` param maps to the **fixture engine**; the `gcp` param does **not** apply (gemini opts in via `BRIDGE_TEST_GEMINI`, out of scope here). The fixture must skip the `gcp` param for extraction with a message naming the axis nuance — do not force extraction through local↔gcp.
- **`bridge/tests/test_no_agents_import.py`** asserts `import bridge` pulls no `agents.*`. Seam modules may import `google.adk`, `a2a`, `contract` freely (none pull `agents`). Keep `bridge/src/bridge/__init__.py` minimal (do **not** make it import the seams/adapters packages) so the guard stays meaningful and `import bridge` stays cheap.
- **Ruff:** `line-length = 100`, `select = ["E","F","I"]` (isort on). Keep imports sorted, lines ≤100.

## Design decisions (made here — do not re-litigate)

- **D1 — `typing.Protocol` + `@runtime_checkable`, not ABCs.** Rationale: the native ADK/a2a-sdk classes (and future GCP ones authored independently in Sprint 2) satisfy the seam **structurally** with no inheritance/import coupling — the "no-op swap" idiom. ABCs would force a base-class import into every adapter incl. third-party ones. Method-only Protocols; `isinstance` smoke-checks presence.
- **D2 — Sessions & Task store seams mirror the native base classes; local adapter = the native in-memory class.** `SessionsSeam` mirrors the `BaseSessionService` subset the Bridge uses; local = `InMemorySessionService`, gcp (Sprint 2) = `VertexAiSessionService`/`DatabaseSessionService` (A13). `TaskStoreSeam` mirrors a2a-sdk `TaskStore` (`save/get/delete/list`); local = `InMemoryTaskStore`, gcp = `DatabaseTaskStore`. No skeleton class for these two — the native class *is* the adapter.
- **D3 — The four Bridge-invented/capability seams get skeleton local adapters** under `bridge/src/bridge/adapters/local/`, one module each, methods raising `NotImplementedError`, constructible, conforming to their Protocol. This is the home M1.2/M1.3/M1.7/M1.12 fill in.
- **D4 — A production local factory** `build_local_adapter(seam: Seam) -> object` in `bridge/src/bridge/adapters/local/__init__.py`, a dict dispatch `Seam -> builder`. The fixture calls it. This seeds the seam-selection home (C3 env wiring layers on later) and keeps the fixture thin. A parallel `build_gcp_adapter` is **not** created now (Sprint 2); the fixture's `gcp` branch skips.
- **D5 — Signatures are a documented starting contract, not frozen.** Where a seam's payload type is owned by a later task (exchange record, skill object, timer), type it `Any`/`object` with a `# M1.x owns the concrete type` note. Downstream tasks may tighten signatures; runtime_checkable smoke tests won't break on signature changes.
- **D6 — Keep the `seam` marker mandatory for the `adapter` fixture.** The grown fixture reads the seam off the test's `@pytest.mark.seam(...)` marker; if a test uses `adapter` without the marker, raise a clear `pytest.fail`/`ValueError`. (The existing collection-time guard already rejects invalid seam names.)

## Ordered steps

### 1. Seam interface modules — `bridge/src/bridge/seams/`
Create one module per seam. Each: module docstring (what the seam is, local vs gcp adapter per `wiki/bridge-seams.md`, the runtime_checkable caveat, the governing invariant), one `@runtime_checkable` `Protocol`. Add each Protocol to `bridge/src/bridge/seams/__init__.py` `__all__` and re-export (keep `Seam`/`ALL_SEAMS`).

- **`sessions.py` → `SessionsSeam`** (task ≈ ADK session; A13 restore is platform-default). Async methods mirroring the used `BaseSessionService` subset: `create_session`, `get_session`, `delete_session`, `list_sessions`, `append_event`. Use `google.adk.sessions.Session` / `google.adk.events.Event` in annotations (import for typing). Docstring: local = `InMemorySessionService`, gcp = `VertexAiSessionService`/`DatabaseSessionService`.
- **`task_store.py` → `TaskStoreSeam`** (durable A2A task, no TTL). Async methods mirroring a2a-sdk `TaskStore`: `save`, `get`, `delete`, `list`. Types from `a2a.types.Task`. Docstring: local = `InMemoryTaskStore`, gcp = `DatabaseTaskStore`; **A5 note** — the persistent/GCP `list` needs a deterministic sort key (the ledger/rows have no timestamp; in-memory rides insertion order).
- **`exchange_store.py` → `ExchangeStoreSeam`** (Bridge-invented; ADR-0003 view-by-default, exchange = A2A `context_id` 1:1). Methods: `get(context_id: str) -> object | None` (None ⇒ unmaterialized, caller uses the derived view), `save(record: object) -> None`, `materialize(context_id: str, *, ...) -> object` (one-way transition on first exchange-only state). Docstring: Phase-1 Address stays a **view over tasks** (ADR-0003) — store present for parity/future materialization; identity is the A2A context, never a new id; A5 deterministic ordering. `# M1.2 defines the concrete exchange record type.`
- **`skill_registry.py` → `SkillRegistrySeam`** (directory of Agent Skills folders; M1.3). Methods: `list_skills() -> list[object]`, `get_skill(name: str) -> object | None`, plus a note that it is the source of the dynamic Agent Card (`name`/`description`) and the process-skill **policy** (disposition thresholds `0.55`/`0.85` per ADR-0002, SLA cadence/deadline/max-nudges per C1). Keep methods minimal; `# M1.3 defines the Skill/policy types` and how the card/policy are surfaced.
- **`scheduler.py` → `SchedulerSeam`** (durable timers + injectable virtual clock; M1.12). Methods: `schedule(timer: object) -> None`, `due(now) -> list[object]`, `cancel(timer_id: str) -> None`. **A7 invariant in the docstring:** `due(now)` marks each returned timer `fired` **in place** — exactly-once emission rides on this; the no-duplicate guarantee must be preserved by M1.12. `# M1.12 defines Timer + the virtual clock`.
- **`extraction.py` → `ExtractionSeam`** (capability axis — ADR-0005). Single method: `extract(document: object, doctype_skill: object) -> Extraction` (return the existing `contract.Extraction`). Docstring: **not** local↔gcp — engines `fixture|gemini|docai` selected by config + per-doctype capability (ADR-0005 resolution order is M1.7); local build = fixture engine; disposition reads signals engine-agnostically (ADR-0004, downstream). `# M1.7 implements the fixture engine + engine resolution; ADR-0004 SignalProvider is M1.6.`

## Gotchas (ordered by how likely they are to bite)
1. **Runtime-checkable Protocols must be method-only.** Adding a data attribute makes `isinstance` raise `TypeError`. Keep every seam Protocol methods-only.
2. **The old placeholder test breaks.** `test_adapter_fixture_yields_local_always` asserts `adapter in {"local","gcp"}` — it MUST be removed/replaced when the fixture starts yielding instances, or the suite goes red.
3. **Extraction axis.** Do not wire extraction through local↔gcp. `local`→fixture engine; `gcp` param skips with the capability-axis message (`wiki/bridge-seams.md` §Axis nuance, C3).
4. **Keep `bridge/__init__.py` from importing the seams/adapters packages.** Importing them pulls adk/a2a into `import bridge` — allowed by the guard (no `agents`) but adds cost and blurs the guard's intent. Leave `__init__.py` minimal.
5. **Skeleton methods raise `NotImplementedError`, not `pass`.** A silent `pass`/`None` would let a dependent task ship half-built behavior undetected. Make the deferral loud and tag it `M1.x`.
6. **Don't invent downstream types.** Exchange record (M1.2), Skill/policy (M1.3), Timer (M1.12) are owned by later tasks — type them `object`/`Any` with a tagged note; do not pre-model aggregates here.
7. **Native base-class signatures are keyword-heavy** (e.g. `BaseSessionService.create_session` takes config objects). Because runtime_checkable checks presence only, mirror method **names** in the Protocol; do not chase exact signatures or you risk the native class not conforming.
