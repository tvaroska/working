**Sprint:** 0 (scaffolding) · **Task line:** `PLAN.md` S0.3
**Depends on:** S0.2 (`bridge/` core project exists — this is the home for the harness) · S0.1 (CI `core` job already runs `uv run pytest` in `bridge/`, so the new parametrized test runs in CI automatically)

**Related:** `wiki/bridge-seams.md` (the seam table + the "same suite runs against both adapters" claim), `docs/lessons-learned.md` A2/A3 (terminal-outcome parity), C3 (the env-var seam-mode contract), C5 (`RemoteA2aAgent` "cover in the shared seam suite"), CLAUDE.md invariants ("Mock↔real parity is terminal-outcome, not ledger-identical"; the six seams).

## Goal (scope of THIS task only)

Establish the **convention** for the "one shared suite, two adapters" pattern **before any seam is built**. Concretely: a parametrized `adapter` fixture (`local` always, `gcp` only when opted in), a registered `@pytest.mark.seam("<name>")` marker over the six canonical seams, a **home** (an importable enumeration) for the Sprint-1 seam interfaces to land in, one placeholder parametrized test that exercises the fixture, and the rule written down.

This ships **NO domain behavior and NO real adapters** — no Sessions/Task-store/Exchange-store/Scheduler/Extraction implementation, no GCP client, no interface bodies. Sprint 1 designs the interfaces; Sprint 2 adds the GCP impls. S0.3 only lays the test-harness convention and the directory they slot into.

**Explicitly NOT in this task:**
- Do **not** implement any seam interface or adapter (local or GCP). The `Seam` enum names them; that is all.
- Do **not** wire real credentials or make any GCP call. The `gcp` adapter branch must `pytest.skip` unless explicitly opted in — CI stays green with the `local` param only.
- Do **not** add the harness to `agents/` (there is no seam there yet; an unused fixture would rot). See "agents-side note" below — S1-6 replicates the pattern by discipline when it needs it.
- Do **not** touch `.github/workflows/ci.yml` — the `core` job already runs `uv run pytest` in `bridge/` and will pick up the new test.
- Do **not** move `contract` or edit `agents/`.

## Where it lives and why

**Home = `bridge/`** (the core project). The six seams are **Bridge-core managed-service boundaries** (CLAUDE.md lists them as the Bridge's seams; the real Bridge + its local/GCP adapters land in `bridge/` in Sprint 1/2, and the "same test suite runs against both adapters" is a `bridge/` suite). The loosely-named "seam tests" already in `agents/tests/` (`test_native_consumer.py`, `test_control_return.py`, `test_collect_loop.py`, `test_mock_multiturn.py`) are **consumer-side integration tests** — a distinct, informal usage of the phrase; they are NOT the six-seam managed-service harness and are left untouched.

Everything in this task is created under `bridge/`. Run all `uv`/`pytest`/`ruff` commands **from inside `bridge/`**.

## Context an executor needs (do not re-derive)

- **The six canonical seams** (CLAUDE.md + PLAN S0.3.2): **Sessions, Task store, Exchange store, Skill registry, Scheduler, Extraction.** Use these exact snake_case keys for the marker + enum: `sessions`, `task_store`, `exchange_store`, `skill_registry`, `scheduler`, `extraction`. (The `wiki/bridge-seams.md` table lists a couple more — Memory bank, A2A client — but PLAN S0.3 and CLAUDE.md pin the harness to these six. Name six.)
- **Two different axes** (`docs/lessons-learned.md` C3, and `wiki/bridge-seams.md` extraction paragraph):
  - The **five storage/infra seams** (sessions, task_store, exchange_store, skill_registry, scheduler) move on the **local ↔ gcp** axis — that is the `adapter` fixture's axis. Per-seam override env vars exist: `BRIDGE_SEAM_MODE=local|gcp` global, `BRIDGE_SEAM_{SESSIONS,TASK_STORE,EXCHANGE_STORE,SKILL_REGISTRY,SCHEDULER}` per-seam (blank = inherit).
  - **Extraction is a *capability* axis, not local/gcp**: `BRIDGE_EXTRACTION_ENGINE=fixture|gemini|docai`. Both real engines are "deployed either way." So `extraction` is a named seam/marker, but the `local`/`gcp` `adapter` fixture does **not** apply to it the same way — document this nuance; do not try to force extraction through the local/gcp parametrization.
- **GCP test opt-in is already specified** (`docs/lessons-learned.md` C3): `BRIDGE_TEST_GCP=1` (and `BRIDGE_TEST_GEMINI=1` for the gemini engine). The `adapter` fixture keys the `gcp` branch off `BRIDGE_TEST_GCP` — use this exact env var so Sprint 2 doesn't invent a second one.
- **Parity rule** (CLAUDE.md; `docs/lessons-learned.md` A2/A3): mock↔real and local↔gcp parity is asserted on the **terminal outcome** (terminal reason + accepted-issuer set), **never** a step-by-step ledger match. The harness doc must state this so Sprint-1 test authors write outcome assertions, not ledger-diff assertions.
- **No-op-swap rule** (CLAUDE.md, ADR-0001): the mock→real and local→GCP swaps must be **no-ops for the agent** — the same test asserts both adapters. That is the whole point of the parametrized fixture.
- **`bridge/` pytest config** (`bridge/pyproject.toml` `[tool.pytest.ini_options]`) currently has only `testpaths` + `addopts = "-ra"`. No markers registered yet. Add the `seam` marker there.
- **Ruff:** `line-length = 100`, `select = ["E", "F", "I"]` (isort on). Keep imports sorted; wrap docstrings/lines ≤100.
- **Isolation guard interaction:** `bridge/tests/test_no_agents_import.py` imports `bridge` and asserts no `agents.*` in `sys.modules`. Keep the new `bridge/src/bridge/seams/` package import-clean (stdlib only — `enum`) and do **not** make `bridge/src/bridge/__init__.py` import it, so the guard stays meaningful and the seams package never drags in `agents`.

3. **`bridge/tests/support/seams.py`** — the harness module. Contents:
   - Module docstring explaining the "one shared suite, two adapters" convention, that `local` always runs and `gcp` runs only under `BRIDGE_TEST_GCP=1`, and pointing at `wiki/bridge-seams.md` for the rule.
   - `def gcp_test_enabled() -> bool:` returns `os.environ.get("BRIDGE_TEST_GCP") == "1"`. (Single source for the opt-in; Sprint 2 will also check real credentials here.)
   - The parametrized fixture:
     ```python
     import os
     import pytest

     ADAPTER_MODES = ("local", "gcp")

     def gcp_test_enabled() -> bool:
         return os.environ.get("BRIDGE_TEST_GCP") == "1"

     @pytest.fixture(params=ADAPTER_MODES, ids=ADAPTER_MODES)
     def adapter(request) -> str:
         """Yield each seam-adapter mode. `local` always; `gcp` only under BRIDGE_TEST_GCP=1.

         Sprint 1 extends this to build the actual adapter instance per seam+mode;
         S0.3 yields the mode string so the convention (and the CI skip) is locked first.
         """
         mode = request.param
         if mode == "gcp" and not gcp_test_enabled():
             pytest.skip("GCP seam adapter requires BRIDGE_TEST_GCP=1 (+ credentials)")
         return mode
     ```
   - Add a NOTE comment marking the Sprint-1 extension point: the fixture will grow a per-seam dispatch (read the `seam` marker off `request.node`, build the matching local/GCP adapter) once interfaces exist; today it returns the mode string only.
