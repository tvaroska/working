# M1.6 — Disposition + classification (`run_disposition_gate`)

**Milestone:** M1 — Bridge Core (local). **Depends on:** M1.4 (classified ledger), M1.5 (issuer canonicalization), M1.3 (skill registry/policy). **Blocks:** M1.7 (fulfillment graph uses the `gate`), M1.8 (edge maps disposition→task-status), M1.9.

## Goal (what "done" means)

A **deterministic, pure** sense-A verdict per artifact: classify the doctype against the hard-coded
label space, read the extraction-derived signals, route on the skill-policy confidence thresholds, and
produce a `Disposition` + a routing `gate` + flags. Then record each doc into the classified ledger
(M1.4) with its **canonical issuer** (M1.5). **A model never mints this verdict** — it is code, exposed
as an authoritative function (lessons A3, ADR-0001).

The single hard acceptance test: `run_disposition_gate` reproduces **`expected_disposition` AND
`expected_gate` for all 8 fixtures** in `wiki/evals/address/expected.json`, with thresholds read from
`skills/address-proof/assets/policy.yaml` (ADR-0002).

## Background facts (verified — do not re-derive)

- **Gate/disposition mapping is fully determined by the fixtures.** Deriving from
  `wiki/evals/address/expected.json` (`expected_gate` → `expected_disposition`):
  | fixture | doctype | legible | overall_conf | flagged_fields | gate | disposition |
  |---|---|---|---|---|---|---|
  | gov-id-clean | gov-id | true | 0.96 | [] | `auto_approve` | accepted |
  | gov-id-expired | gov-id | true | 0.93 | ["expiry"] | `hitl_review` | pending |
  | bill-powerco-clean | utility-bill | true | 0.97 | [] | `auto_approve` | accepted |
  | bill-powerco-clean-2 | utility-bill | true | 0.95 | [] | `auto_approve` | accepted |
  | bill-aquautil-clean | utility-bill | true | 0.96 | [] | `auto_approve` | accepted |
  | bill-aquautil-clear | utility-bill | true | 0.72 | [] | `hitl_review` | pending |
  | bill-aquautil-blurry | utility-bill | **false** | 0.30 | [] | `resubmit` | rejected |
  | passport-unsupported | **passport** | true | 0.94 | [] | `unsupported` | rejected |

- **The gate routing algorithm that reproduces the table (ORDER MATTERS):**
  1. **type_match** — if `doctype ∉ {gov-id, utility-bill}` → `gate=unsupported`, `disposition=rejected`.
     (Must be first: passport is legible/high-conf but must be `unsupported`, not `auto_approve`.)
  2. **quality gate** — if `legible is False` **or** `overall_confidence < resubmit_below (0.55)` →
     `gate=resubmit`, `disposition=rejected`.
  3. **confidence gate** — if `overall_confidence >= auto_approve_at (0.85)` **and no flags** →
     `gate=auto_approve`, `disposition=accepted`.
  4. **else** → `gate=hitl_review`, `disposition=pending`. (Catches: 0.55 ≤ conf < 0.85 with no flags,
     e.g. bill-aquautil-clear 0.72; and conf ≥ 0.85 **with** flags, e.g. gov-id-expired flagged expiry.)
  - "flags" = `Extraction.flagged_fields` (non-empty blocks auto-approve). Do NOT parse dates / run
    `validation.yaml` date math in M1.6 — the fixture extraction pre-computes `legible` and
    `flagged_fields` (the "unexpired?" rule already surfaced as `flagged_fields=["expiry"]`). Date-rule
    evaluation belongs upstream in the extraction engine (M1.7), not here.
  - `escalate` / `extraction_error` gates are **out of scope** — they are the resubmission-loop
    outcomes owned by M1.7 (the fulfillment graph). M1.6 is the per-artifact verdict only.

- **Thresholds come from the skill policy (ADR-0002).** `DispositionThresholds(resubmit_below=0.55,
  auto_approve_at=0.85)` already exists in `bridge/src/bridge/skills.py` and is loaded from
  `skills/address-proof/assets/policy.yaml` by `LocalSkillRegistry` (M1.3). `run_disposition_gate` reads
  resolved threshold values, never literals. Default to `DispositionThresholds()` so gates always resolve
  when a key is omitted (ADR-0002 defaults-with-override).

- **Label space is HARD-CODED, not skill-derived (lessons A8 — the "honesty trap").** Define
  `CANDIDATE_DOCTYPES = ("gov-id", "utility-bill")` as a code constant. The `address-proof` skill *also*
  carries `bridge-candidate-doctypes: "gov-id utility-bill"`, but A8 is explicit: the core's label space
  is deliberately hard-coded and making it skill-derived is a **separate coordinated change** that would
  break the sense-A tests. For M1.6: hard-code it, add a one-line comment citing A8. Do not wire it to
  the skill.

- **Issuer canonicalization (M1.5).** `bridge.canonical.canonicalize_issuer(raw)` is idempotent. The
  fixture extractions already carry canonical `fields.issuer` (`"power-co"`), but M1.6 MUST still call
  `canonicalize_issuer(extraction.fields.issuer)` when building the `LedgerEntry` — in the real flow the
  extraction engine (M1.7) produces raw issuers; idempotency makes this safe for both. gov-id has
  `issuer=None` → `canonicalize_issuer(None)` returns `None`.

- **ADR-0004 four-signal contract must be the shape from day one.** Define the fixed `DispositionSignals`
  value object + `Signal` + `SignalProvider` interface now, ship exactly ONE provider
  (`ExtractionDerivedSignalProvider`). It populates `legibility` and `confidence`
  (+`fields_needing_review` from `flagged_fields`) from the extraction, and `type_match` from
  classification against `CANDIDATE_DOCTYPES`. **`completeness` is left unpopulated** (sense B is the
  app's — ADR-0004). Absent signal = "not evaluated", not "failed".

- **`SignalProvider` is an interface, NOT one of the six seams.** The `Seam` enum is fixed (sessions,
  task_store, exchange_store, skill_registry, scheduler, extraction). Do **not** add it to `seams/`, do
  not add a `@pytest.mark.seam` marker for it. It's a plain Protocol in `bridge/src/bridge/`.

- **M1.6 consumes an `Extraction`; it does NOT run extraction.** The extraction seam (`extract()`) and
  the fixture engine are M1.7 (still `NotImplementedError`). `run_disposition_gate` operates on an
  already-produced `contract.Extraction`. Tests build `Extraction` inline or from the eval JSON.

## Import discipline (hard invariants — will fail CI if violated)

- `bridge/` **never imports `agents/`** (guarded by `bridge/tests/test_no_agents_import.py`). Build the
  disposition/classification logic fresh in `bridge/`; parity with the mock/agents side holds via the
  shared suite, not imports.
- New modules must **not** be imported from `bridge/src/bridge/__init__.py` — keep `import bridge` cheap
  and the no-agents guard clean (same rule `aggregate.py`, `ledger.py`, `canonical.py` follow).
- Avoid an import cycle between the two new modules: put `DispositionSignals`/`Signal`/`SignalProvider`/
  `ExtractionDerivedSignalProvider` **and** `CANDIDATE_DOCTYPES` in `signals.py` (the lower layer, no
  dependency on disposition); `disposition.py` imports `DispositionSignals` from `signals.py`. Do NOT
  make `signals.py` import `disposition.py`.

## Files to create

### 1. `bridge/src/bridge/signals.py` (new)
ADR-0004 signal contract + the one Phase-1 provider + the label space.
- `CANDIDATE_DOCTYPES: tuple[str, ...] = ("gov-id", "utility-bill")` — hard-coded (lessons A8, cite it).
- `class SignalSource(StrEnum)`: `EXTRACTED`, `REPORTED`, `COMPUTED`, `MOCK`.
- `class Signal(BaseModel, frozen=True)`: `value: float | str`, `source: SignalSource`, `detail: str | None = None`.
- `class DispositionSignals(BaseModel, frozen=True)` (`extra="forbid"`): `legibility: Signal | None = None`,
  `type_match: Signal | None = None`, `confidence: Signal | None = None`,
  `fields_needing_review: list[str] = Field(default_factory=list)`, `completeness: Signal | None = None`,
  `failed_rules: list[str] = Field(default_factory=list)`.
- `class SignalProvider(Protocol)` with `def signals(self, document: object, doctype_skill: object,
  extraction_result: Extraction) -> DispositionSignals: ...` (signature per ADR-0004; `document`/
  `doctype_skill` are `object` placeholders like the extraction seam does — M1.7 concretizes them).
- `class ExtractionDerivedSignalProvider:` implementing it:
  - `type_match` = `Signal(value=1.0 if extraction.fields.doctype in CANDIDATE_DOCTYPES else 0.0,
    source=EXTRACTED, detail=extraction.fields.doctype)`.
  - `legibility` = `Signal(value=1.0 if extraction.legible else 0.0, source=EXTRACTED)` when
    `extraction.legible is not None`, else `None`.
  - `confidence` = `Signal(value=extraction.overall_confidence, source=EXTRACTED)` when not None, else `None`.
  - `fields_needing_review` = `list(extraction.flagged_fields)`.
  - `completeness` = `None` (sense B — ADR-0004; leave unpopulated).

### 2. `bridge/src/bridge/disposition.py` (new)
The authoritative deterministic gate + classification + ledger recording.
- `class Gate(StrEnum)`: `AUTO_APPROVE = "auto_approve"`, `HITL_REVIEW = "hitl_review"`,
  `RESUBMIT = "resubmit"`, `UNSUPPORTED = "unsupported"`. **Values MUST equal the `expected_gate`
  strings** in the eval JSON.
- `class DispositionResult(BaseModel, frozen=True)` (`extra="forbid"`): `disposition: Disposition`,
  `gate: Gate`, `flags: list[str] = Field(default_factory=list)`, `signals: DispositionSignals`.
- `def run_disposition_gate(signals: DispositionSignals, *, thresholds: DispositionThresholds =
  DispositionThresholds()) -> DispositionResult` — pure; implements the 4-step ordered algorithm above.
  Reads `signals.type_match.value`, `signals.legibility.value`, `signals.confidence.value`,
  `signals.fields_needing_review`. Treat a `None` confidence conservatively: cannot auto-approve →
  falls through to hitl_review (only matters off-fixture; document it). `flags = signals.fields_needing_review`.
- `def classify_document(doc_id: str, extraction: Extraction, *, thresholds: DispositionThresholds =
  DispositionThresholds(), provider: SignalProvider | None = None) -> tuple[LedgerEntry,
  DispositionResult]` — the "record each doc into the ledger with its canonical issuer" step:
  1. `provider = provider or ExtractionDerivedSignalProvider()`.
  2. `signals = provider.signals(None, None, extraction)`.
  3. `result = run_disposition_gate(signals, thresholds=thresholds)`.
  4. `issuer = canonicalize_issuer(extraction.fields.issuer)`.
  5. build `LedgerEntry(id=doc_id, doctype=extraction.fields.doctype, issuer=issuer,
     disposition=result.disposition, extraction=extraction)`.
  6. return `(entry, result)`. (The `gate` is returned via `result` for M1.7; `LedgerEntry` has no gate
     field — do not invent one.)
  - Keep `run_disposition_gate` (routing over signals) and `classify_document` (provider + canonicalize
    + build entry) separate so the routing core stays engine-agnostic (ADR-0004).
- Module docstring: cite ADR-0002 (thresholds), ADR-0004 (signals), lessons A3 (code decides, model never
  mints acceptance) and A8 (hard-coded label space); note it's kept out of `__init__.py`.

## Acceptance criteria
1. `run_disposition_gate` + `classify_document` reproduce **`expected_disposition` and `expected_gate`
   for all 8 fixtures**, thresholds sourced from `skills/address-proof/assets/policy.yaml` via the M1.3
   registry.
2. Recorded `LedgerEntry.issuer` is the **canonical** issuer (M1.5) for bills; `None` for gov-id.
3. `DispositionSignals`/`Signal`/`SignalProvider` exist as the fixed ADR-0004 shape with exactly one
   provider; `completeness` unpopulated.
4. Gate routing is deterministic and pure (no model, no I/O) — a model can never mint acceptance (A3).
5. Label space is hard-coded (A8), not skill-derived.
6. `run_disposition_gate`/classification live in `bridge/`, import no `agents/` module, and are not added
   to `bridge/__init__.py`.
7. Full suite green: `cd bridge && uv run ruff check . && uv run pytest` (and `agents/` unchanged).
   `bridge/tests/test_no_agents_import.py` still passes.

## Gotchas recap
- **Gate order is load-bearing** — type_match → quality → confidence(+flags) → hitl. Getting the order
  wrong silently passes some fixtures and fails others (passport, gov-id-expired are the tells).
- **Do not run date/validation.yaml math** — flags come pre-computed in `Extraction.flagged_fields`.
- **`escalate`/`extraction_error` are M1.7**, not M1.6.
- **Canonicalize on record even though fixtures are pre-canonical** — idempotent; the real engine emits raw.
- **No new seam**; `SignalProvider` is a plain Protocol, no `@pytest.mark.seam`.
- **Keep the modules out of `__init__.py`** and out of `seams/`.
