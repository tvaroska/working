# M1.13 — Mock→real swap + shared seam suite green

**Task (PLAN.md, Milestone 1):** Point the address agent at the *real* Bridge
(`bridge/`) by **card-URL swap only**, then run the shared suite across **both** the
mock Bridge and the real Bridge on local adapters and assert **terminal-outcome
parity** — same terminal reason + accepted-issuer set, never a ledger-identical match
(lessons **A2**). Cover three scenarios: `gov-id-instant`, distinct-issuer `two-bills`,
and `reject-resubmit`. This is the capstone integration proof of Milestone 1.

## Bottom line up front

- The production agent is **already** swap-ready: the durable graph
  (`agents/src/agents/address/graph.py`) consumes the Bridge as a native
  `RemoteA2aAgent` whose *only* Bridge coupling is the Agent Card URL
  (`build_collect_node(card_url)`). **No production agent code changes.** The proof is
  that the *same* `build_test_app(card_url)` graph reaches the same terminal outcome
  whether `card_url` points at the mock or the real Bridge.
- The real Bridge already serves the identical wire contract (M1.8/M1.9:
  `bridge/src/bridge/edges/a2a/app.py`), with named collect plans that deliberately
  mirror the mock scenarios (`bridge/src/bridge/edges/a2a/plan.py`).
- **What's missing** is (1) `agents/` cannot import `bridge/` today, and (2) the
  native durable-graph consumer has **never been driven against the real Bridge** —
  `bridge/tests/test_edge_a2a.py` explicitly defers "the deeper native-consumer
  round-trip through the real `RemoteA2aAgent`" to M1.13. This task adds the
  cross-package **dev** dependency, a live-real-Bridge test server, and one
  parametrized parity suite that drives the graph against both backends.

## Governing invariants (must hold)

- **`bridge/` never imports `agents/`.** The new dependency is one-directional:
  `agents/` (tests only) imports `bridge/`. This is allowed and precedented (lessons
  **A9**: demo/console furniture importing `bridge` is fine). Keep
  `bridge/tests/test_no_agents_import.py` green (do not touch `bridge/`).
- **Parity is terminal-outcome, not ledger-identical (A2).** Assert only the
  destination: `is_satisfied(...).done` and the sorted `accepted_issuers` set (plus
  `status.terminal is True`). Do NOT compare ledgers step-by-step. The mock and real
  legitimately diverge turn-by-turn (e.g. mock `reject-resubmit` is one terminal turn
  with a rejected *passport*; real is a park→resume with a rejected *blurry bill*).
- **LLM routes, code decides (A3).** The terminal decision is
  `agents/src/agents/address/satisfaction.py::is_satisfied` (deterministic). Use it —
  never assert a model-derived outcome.
- Keep the agent's production surface untouched: the whole point is "the difference
  between demos is the agent, not the Bridge" and "the swap is a no-op for the agent."

## Architecture recap (how the pieces already fit)

- `agents/src/agents/address/graph.py` — durable `Workflow`: `collect`
  (`RemoteA2aAgent`, built by `build_collect_node(card_url)`) → deterministic `gate`
  (`is_satisfied`) → `present`, with a conditional `--[again]-->` loop-back.
- `agents/tests/support/app.py::build_test_app(card_url)` — assembles that graph +
  resumable `App` pointed at an arbitrary card URL. **Reuse this unchanged** for both
  backends.
- `agents/src/bridge_client/remote_consumer.py` — the send-path interceptor that
  (a) injects the structured `CollectRequest` DataPart, (b) threads the exchange
  `context_id`, and (c) **re-detects a pending park/resume inside a `Workflow`** and
  stamps the parked `task_id`/`context_id` (the S1-6 fix). This is the machinery that
  must now prove itself against the *real* Bridge. It is wired automatically by
  `build_collect_node` (via `build_bridge_remote_agent(collect_request=...)`).
- Mock: `agents/src/agents/mock_bridge/app.py::create_app(base_url, scenario=, park=,
  hold_seconds=)`; scenarios in `.../scenarios.py` (`gov-id-instant`, `two-bills`,
  `reject-resubmit`).
- Real: `bridge/src/bridge/edges/a2a/app.py::create_app(base_url, collect_plan=,
  hold_seconds=, strict=, task_store=)`; plans in `bridge/src/bridge/edges/a2a/plan.py`
  (`GOV_ID_INSTANT`, `TWO_BILLS_DISTINCT`, `REJECT_RESUBMIT`).

### Park semantics differ between backends — the driver must be park-agnostic

| scenario | mock config | mock park? | real config | real park? |
|---|---|---|---|---|
| gov-id-instant | `scenario="gov-id-instant"`, `park=False` | no (1 terminal turn) | `collect_plan=GOV_ID_INSTANT` | no (1 terminal round) |
| two-bills | `scenario="two-bills"`, **`park=True`** | yes (park→resume, round1 = 2 bills) | `collect_plan=TWO_BILLS_DISTINCT` | yes (round0 non-terminal → INPUT_REQUIRED → resume) |
| reject-resubmit | `scenario="reject-resubmit"`, `park=False` | **no** (1 terminal turn: rejected passport + accepted gov-id) | `collect_plan=REJECT_RESUBMIT` | **yes** (round0 blurry bill non-terminal → park → resume → gov-id) |

Two non-obvious points captured from source:

1. **Mock `two-bills` MUST set `park=True`.** With `park=False` the mock *completes*
   round 0 (one bill, `terminal=False`); the graph gate routes `again`, but a
   content-less loop-back re-entry sends no parts to the peer (`RemoteA2aAgent`:
   "No parts to send…"), so the gate re-reads the same 1-bill turn and the loop spins
   to `MAX_ROUNDS` with `done=False` (lessons **A12**). `park=True` makes the second
   bill arrive via the park/resume within a single collect task instead.
2. **Mock `reject-resubmit` MUST stay `park=False`** — it is modeled as a *single*
   terminal turn (resubmit is non-resumable, A1/A12). The real Bridge reaches the same
   terminal outcome via a park→resume (its `REJECT_RESUBMIT` plan has a non-terminal
   round 0). This mismatch is exactly why parity is terminal-outcome only.

Because park structure differs, the parity **driver must be park-agnostic**: run the
graph, and whenever the run pauses on a `LongRunningFunctionTool` call, feed a
matching `FunctionResponse` and continue; repeat until a run completes with no pending
pause; then read the terminal turn. This single driver handles 0-park, 1-park, and
(defensively) N-park uniformly.

### Expected terminal-outcome fingerprints (both backends must match these)

- `gov-id-instant` → `done=True`, `accepted_issuers=set()`, `terminal=True`
  (one accepted gov-id; gov-id path has no bill issuers).
- `two-bills` → `done=True`, `accepted_issuers={"power-co", "aqua-util"}`,
  `terminal=True`.
- `reject-resubmit` → `done=True`, `accepted_issuers=set()`, `terminal=True`
  (terminal outcome is one accepted gov-id).

### Step 3 — Write the parity suite

Create `agents/tests/test_mock_real_parity.py`. Follow the existing sync-test +
`asyncio.run(...)` idiom used by `agents/tests/test_durable_graph.py` (agents has **no**
`conftest`/anyio plugin — do NOT introduce `@pytest.mark.anyio`).

Reuse from `test_durable_graph.py` (import or replicate the small helpers):
`_make_runner` (via `build_test_app` + `InMemorySessionService` +
`InMemoryArtifactService`), `_find_paused_call`, `_collect_message`, `_resume_message`,
and the fingerprint helper (`is_satisfied(_coerce_status(turn))`). In-memory services
are sufficient here — S1-6 already proved durability; M1.13 proves *swap parity*.

Implement the park-agnostic driver:

```python
MAX_RESUME_ROUNDS = 6  # defensive cap so a broken integration fails fast, not hangs

async def _drive_to_terminal(card_url: str) -> dict | None:
    session_service = InMemorySessionService()
    runner = _make_runner(card_url, session_service)
    await session_service.create_session(app_name=APP_NAME, user_id=PARTY, session_id="s1")
    message = _collect_message()
    for _ in range(MAX_RESUME_ROUNDS):
        events = [e async for e in runner.run_async(
            user_id=PARTY, session_id="s1", new_message=message)]
        paused = _find_paused_call(events)
        if paused is None:
            break
        message = _resume_message(paused)
    session = await session_service.get_session(
        app_name=APP_NAME, user_id=PARTY, session_id="s1")
    await runner.close()
    return session.state.get(TERMINAL_TURN_STATE_KEY)
```

Scenario config table (a small module-level dict), one entry per scenario mapping to
`(mock_kwargs, real_kwargs, expected_done, expected_accepted_issuers)` per the tables
above. Note the mock `two-bills` entry sets `park=True`.

Parametrize the test over the three scenarios; **inside each test drive BOTH backends
and compare** (this is the honest "same destination" assertion and also proves the
card-URL-only swap, since both calls use the identical `build_test_app` graph):

```python
@pytest.mark.parametrize("scenario", ["gov-id-instant", "two-bills", "reject-resubmit"])
def test_terminal_outcome_parity(scenario):
    cfg = SCENARIO_CONFIG[scenario]
    with LiveMockServer(hold_seconds=0.05, **cfg.mock_kwargs) as mock:
        mock_turn = asyncio.run(_drive_to_terminal(mock.card_url))
    with LiveBridgeServer(hold_seconds=0.02, **cfg.real_kwargs) as real:
        real_turn = asyncio.run(_drive_to_terminal(real.card_url))

    for label, turn in (("mock", mock_turn), ("real", real_turn)):
        assert turn is not None, f"{label}: no terminal turn recorded"
        assert turn["status"]["terminal"] is True, f"{label}: not terminal"
        res = is_satisfied(_coerce_status(turn))
        assert res.done is cfg.expected_done, f"{label}: done mismatch"
        assert set(res.accepted_issuers) == cfg.expected_accepted_issuers, f"{label}: issuers"

    # Terminal-outcome parity (A2): same destination, never ledger-identical.
    assert _fingerprint(mock_turn) == _fingerprint(real_turn)
```

where `_fingerprint(turn) = (is_satisfied(_coerce_status(turn)).done,
frozenset(is_satisfied(_coerce_status(turn)).accepted_issuers))`.

## Risk / difficulty notes for the implementer

The mechanical parts (dep wiring, live server, driver, assertions) are
straightforward and pattern-following. The real risk is Step 4: this is the
**first-ever** run of the native `RemoteA2aAgent` durable-graph consumer against the
*real* Bridge edge's park/resume. All the composing pieces are individually proven
(mock park/resume through the graph in `test_durable_graph.py`; real edge park/resume
at the wire level in `bridge/tests/test_edge_a2a.py`), and both sides share the exact
same A2A contract — so composition *should* work — but if it does not, diagnosis lives
in subtle A2A/ADK async event-ordering territory (interceptor resume detection under
`Workflow` ordering, `current_task` population, `custom_metadata` propagation). Budget
for that.
