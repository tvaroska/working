# M1.11 — Dual-path routing

**Milestone:** M1 — Bridge Core (local) · **Depends on:** M1.7 (`bridge/fulfillment.py` Path-B extraction graph), M1.8 (`bridge/edges/a2a/` inbound A2A edge — the Path-A transport + requester surface), M1.10 (`bridge/edges/a2ui/` — Path-B intake feed) · **Blocks:** M1.13 (mock→real swap + shared seam suite) · **Design roots:** `wiki/bridge-dual-path.md`, `wiki/bridge-edges.md` ("The choice is invisible to the requester … decided only by what kind of Part arrives"), lessons A2/A3.

## 1. Goal (what "done" means)

The Bridge fulfills a party's response to an already-open exchange in one of two modes, **decided only by what kind of Part arrives**, and **indistinguishable to the requester** (the servicer agent on the A2A edge):

| Path | Party | Arriving Part | Bridge does |
|---|---|---|---|
| **Path A — structured** | has an agent | a structured **`Extraction`** JSON DataPart (already normalized) | **validate-only**: schema-validate + run the deterministic disposition gate (`classify_document`). **No extraction call** (`engine.extract` is never invoked). |
| **Path B — portal** | human | file (PDF) / free-text / form | run the **M1.7 extraction graph** (`run_fulfillment`), which calls `engine.extract`. |
| **Operator-fulfilled** | internal human | upload on the party's behalf | **as Path B** (priority nuance deferred — see §7). |

Both paths **converge** on the same downstream: a classified `LedgerEntry` → the same `ExchangeTurn{CollectionStatus}` the requester already consumes. Same fixture in via either path ⇒ identical terminal disposition/entry (this is the "indistinguishable to the requester" acceptance, and it is terminal-outcome parity — lessons A2).

**Invariant preserved (A3, "code decides"):** a Path-A structured response is **not** auto-accepted. The agent's structured claim still passes through the *same* deterministic disposition gate as Path B — it can still land HITL/rejected. Path A only skips OCR/extraction, not the verdict.

## 2. Key facts learned from the codebase (do not re-derive)

1. **`run_fulfillment` (M1.7, `bridge/src/bridge/fulfillment.py`)** is a pure async state machine: `try engine.extract` (→ `ExtractionError` → `EXTRACTION_ERROR` phase) → `classify_document(doc_id, extraction)` → route on `result.gate` into `{AUTO_APPROVE | HITL | UNSUPPORTED | RESUBMIT | ESCALATED}`. **The gate→Phase routing block (the `if gate == …` ladder) is the exact logic Path A must reuse verbatim** so the two paths converge. It is currently inlined in `run_fulfillment` — factor it out (see §3.A).
2. **`classify_document(doc_id, extraction, *, thresholds, provider)` (M1.6, `bridge/src/bridge/disposition.py`)** is the shared, deterministic, engine-agnostic core both paths already route through. It takes an `Extraction` (not a document) and returns `(LedgerEntry, DispositionResult)`. **Path A = `classify_document` with no `engine.extract` before it.**
3. **The A2A executor (M1.8, `bridge/src/bridge/edges/a2a/executor.py`)** currently drives arrivals **only** via the `CollectPlan` fixture stand-in: for each `fid` in the round it calls `await self._engine.extract(FixtureDocument(fixture_id=fid), None)` then `classify_document(...)`. That is effectively a Path-B arrival (engine called). **There is no Path-A branch today and no inbound-Part inspection on arrivals.** M1.11 adds the dispatch. Do **not** rip out the plan-driven Path-B arrivals — they stay as the default and keep M1.8's tests green.
4. **Wire encoding (`agents/src/bridge_client/wire.py`, replicate — never import it):** inbound domain payloads ride as JSON DataParts read with `a2a.helpers.proto_helpers.get_data_parts(message.parts)`. A `CollectRequest` DataPart has keys `party`/`skill` (no `fields`); a Path-A `Extraction` DataPart has a top-level `fields` key (see `contract.Extraction`/`ExtractedFields`). **Distinguish by shape** (mirrors how `wire.task_to_exchange_turn` selects the `ExchangeTurn` part by the presence of `"status"`, and `requirements_from_task` by `"requirements"`).
5. **`contract.Extraction`** (`contract/src/contract/models.py`) is the Path-A payload schema: `fields: ExtractedFields` (+ confidence signals). `Extraction.model_validate(datapart_dict)` is the schema-validation step for Path A.
6. **`create_app(..., engine=…)` (`bridge/src/bridge/edges/a2a/app.py`)** already injects the extraction engine into `BridgeExecutor`, so a **spy engine** (records `extract` calls) can be injected in tests to prove "no extraction call" on Path A.
7. **A2UI (`bridge/src/bridge/edges/a2ui/intake.py`)** `submit_intake` already feeds `run_fulfillment` = **Path B** (human upload). Leave it; M1.11 documents A2UI as always-Path-B (optionally route it through the shared dispatcher for symmetry — low priority, §7).
8. **Test idiom:** async tests use `@pytest.mark.anyio` (`bridge/tests/conftest.py`); server tests drive the Starlette edge via `httpx.AsyncClient(transport=httpx.ASGITransport(app=app), …)` (see `bridge/tests/test_edge_a2a.py` — no uvicorn). Add `@pytest.mark.seam("extraction")` where a test drives the engine.
9. **Import discipline (hard):** `bridge/` never imports `agents/` (`bridge/tests/test_no_agents_import.py`). New modules stay **out of `bridge/__init__.py`** (every non-`__init__` bridge module follows this). Edges may import core + seams + adapters; core must not import edges.

## 3. Files to create / modify

### A. `bridge/src/bridge/fulfillment.py` (MODIFY — factor the shared router + add Path A)

1. **Extract `route_disposition`** — a pure function holding the current gate→Phase ladder:
   ```python
   def route_disposition(
       entry: LedgerEntry,
       result: DispositionResult,
       *,
       attempts: int = 0,
       max_resubmissions: int = 3,
   ) -> FulfillmentResult:
       """Route a completed disposition (gate) into a FulfillmentResult phase.

       The SHARED convergence point for both fulfillment paths: Path B
       (run_fulfillment, after engine.extract) and Path A (validate_only, no
       extract) both funnel through here, so the same signals reach the same
       terminal outcome — indistinguishable to the requester (wiki/bridge-dual-path).
       """
   ```
   Move the existing `if gate == Gate.AUTO_APPROVE … elif RESUBMIT …` block (fulfillment.py lines ~196–262) into it verbatim (it already uses `result.gate`, `entry`, `attempts`, `max_resubmissions`). `run_fulfillment` becomes: `try extract (except ExtractionError → EXTRACTION_ERROR) → derive doc_id → entry,result = classify_document(...) → return route_disposition(entry, result, attempts=attempts, max_resubmissions=max_resubmissions)`. **No behavior change** — `test_fulfillment.py` must stay green unchanged.

2. **Add `validate_only`** — the Path-A entrypoint (sync, no engine):
   ```python
   def validate_only(
       extraction: Extraction,
       *,
       doc_id: str | None = None,
       thresholds: DispositionThresholds = DispositionThresholds(),
       attempts: int = 0,
       max_resubmissions: int = 3,
   ) -> FulfillmentResult:
       """Path A: validate a structured response + run the disposition gate.

       NO extraction call — the party's agent already normalized the document; the
       Bridge only schema-validates (the caller passes an already-validated
       Extraction) and runs the SAME deterministic gate as Path B (A3: a structured
       claim can still be HITL/rejected — it is not auto-accepted). Converges via
       route_disposition, so the requester cannot tell the path apart.
       """
       if doc_id is None:
           doc_id = "path-a-doc"
       entry, result = classify_document(doc_id, extraction, thresholds=thresholds)
       return route_disposition(entry, result, attempts=attempts, max_resubmissions=max_resubmissions)
   ```
   Add `Extraction` to the `contract` import and `classify_document` is already imported. Add `route_disposition`, `validate_only` to `__all__`.

   *Note:* Path A has no `ExtractionError` branch — malformed structured input is a **contract/schema** failure surfaced at the edge (`Extraction.model_validate` raises), not a disposition. Do not invent a validation-error phase.

### B. `bridge/src/bridge/edges/a2a/dispatch.py` (CREATE — dispatch by the arriving Part + converged entrypoint)

Module docstring: dual-path dispatch (`wiki/bridge-dual-path.md`); the path is decided **only by what kind of Part arrives**; both paths converge on `route_disposition`; imports `contract` + `a2a` + core (`fulfillment`); never imports `agents`; kept out of `bridge/__init__.py`.

```python
class PathKind(StrEnum):
    A = "path_a"   # structured Extraction response → validate-only, no extract
    B = "path_b"   # file / text / form → extraction graph (run_fulfillment)

def looks_like_extraction(data: object) -> bool:
    """A DataPart is a Path-A structured response iff it schema-shapes as Extraction
    (top-level 'fields'). A CollectRequest DataPart (party/skill, no 'fields') is NOT."""
    return isinstance(data, dict) and "fields" in data

def classify_arrival(parts, *, operator: bool = False) -> PathKind:
    """Dispatch by the arriving A2A Part(s) (wiki/bridge-dual-path).

    - operator-fulfilled → Path B (an internal human upload; lessons/wiki dual-path).
    - any FilePart or TextPart present (raw doc / free text) → Path B.
    - a structured DataPart that shapes as Extraction → Path A.
    - otherwise (no recognizable structured response) → Path B (default: extract).
    """
    if operator:
        return PathKind.B
    if any(_is_file_part(p) or _is_text_part(p) for p in parts):
        return PathKind.B
    for data in get_data_parts(parts):
        if looks_like_extraction(data):
            return PathKind.A
    return PathKind.B

async def route_arrival(
    path: PathKind,
    *,
    extraction: Extraction | None = None,
    document: object | None = None,
    engine: ExtractionSeam,
    thresholds: DispositionThresholds | None = None,
    attempts: int = 0,
    max_resubmissions: int = 3,
) -> FulfillmentResult:
    """Converged dual-path entrypoint. Path A → validate_only (no engine); Path B →
    run_fulfillment (engine). Both return the same FulfillmentResult shape so callers
    (and the requester) cannot distinguish the fulfillment mode."""
    thr = thresholds or DispositionThresholds()
    if path is PathKind.A:
        if extraction is None:
            raise ValueError("Path A requires a validated Extraction")
        return validate_only(extraction, thresholds=thr, attempts=attempts, max_resubmissions=max_resubmissions)
    if document is None:
        raise ValueError("Path B requires a document")
    return await run_fulfillment(document, engine=engine, thresholds=thr, attempts=attempts, max_resubmissions=max_resubmissions)
```
- `_is_file_part` / `_is_text_part`: inspect the a2a proto `Part` — a `Part` wraps a `oneof` (`p.HasField("file")` / `p.HasField("text")` / `p.HasField("data")`). Verify the exact field names against the installed `a2a-sdk` (`a2a.types.Part`) at build time; the proto uses `HasField`. Keep these two helpers tiny and defensive (`getattr`/`HasField` guarded).
- `__all__ = ["PathKind", "classify_arrival", "looks_like_extraction", "route_arrival"]`.

### C. `bridge/src/bridge/edges/a2a/executor.py` (MODIFY — wire dispatch into the real edge)

Add a **Path-A branch** to `execute`; keep the plan-driven Path-B arrivals as the default (backward-compatible with M1.8 tests).

1. After parsing/handling the inbound message, compute the arrival path over the **non-`CollectRequest`** parts:
   - On first turn: `datas[0]` is the `CollectRequest`; the Path-A `Extraction` (if any) is a *second* DataPart in the same message, or arrives on a follow-up/resume message. Use `classify_arrival(message.parts)` but treat a lone `CollectRequest` (no `fields` part, no file/text) as Path B (the default plan arrival). `classify_arrival` already returns `B` for a CollectRequest-only message (no `fields`, no file/text).
   - Detect a Path-A structured part explicitly: scan `get_data_parts(message.parts)` for the first dict with `looks_like_extraction(d)` → that is the party's structured response.
2. **Path A branch** (structured Extraction present):
   - `extraction = Extraction.model_validate(structured_data)` (schema-validate; a failure is a contract error — let it raise / return a JSON-RPC error).
   - `result = validate_only(extraction, doc_id=f"{context.task_id}-doc-{len(legs)}")` — **no `engine.extract`**.
   - `entry = result.entry`; apply the same M1.9 rejected-entry `reason_code`/`message` stamping the current code does; `stamp_ledger_entry(leg, entry)`; append leg.
   - Terminality: reuse `plan.is_terminal(r)` for the current round (so a Path-A round can still be scripted terminal/non-terminal and park/resume stays symmetric). For the default `GOV_ID_INSTANT`-style single accepted structured doc this is terminal ⇒ COMPLETED.
3. **Path B branch** (default): the existing `for fid in collect_round.fixture_ids:` loop, unchanged.
4. Everything downstream (advisory satisfaction, `build_exchange_turn`, RequirementsList, `_status_for`, emit sequence, park/resume) is **shared** — both branches feed the same leg-task list and the same `ExchangeTurn` emission. This is what makes the two paths indistinguishable to the requester.
5. Import `classify_arrival`, `looks_like_extraction`, `PathKind` from `.dispatch`, `validate_only` from `bridge.fulfillment`, `Extraction` from `contract`.

**Keep the executor change additive and minimal.** Do not reroute the Path-B branch through `run_fulfillment` (it would introduce HITL/resubmit phases the edge doesn't currently model and could perturb M1.8's park/resume tests). Path-B stays `engine.extract` + `classify_document` exactly as today.

## 6. Acceptance criteria (all must hold)
1. Dispatch is by the arriving Part: `classify_arrival` routes a structured `Extraction` DataPart → Path A, and file/text/form (and operator-fulfilled) → Path B (`wiki/bridge-dual-path.md`).
2. **Path A is validate-only with no extraction call** — `validate_only` runs `classify_document` (the deterministic gate) and never invokes `engine.extract` (proven by a spy engine).
3. **Path B runs the M1.7 extraction graph** (`engine.extract` invoked).
4. **Indistinguishable to the requester:** the same fixture via Path A vs Path B yields the same terminal disposition/ledger entry and the same `ExchangeTurn` (terminal-outcome parity, A2).
5. **A3 preserved:** a Path-A structured response is not auto-accepted; it passes the same deterministic gate (can be HITL/rejected).
6. Both paths converge through the shared `route_disposition`; `run_fulfillment` behavior is unchanged (`test_fulfillment.py` green).
7. `bridge/` imports no `agents/` (guard green); new modules absent from `bridge/__init__.py`; `uv run pytest` + `uv run ruff check` green in `bridge/`; `agents/` unaffected.
