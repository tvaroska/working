## Design decisions (baked in — don't re-litigate)

1. **`pnpm test` = Vitest unit tests, run once (NOT watch, NOT Playwright).** Vitest defaults to
   **watch mode** when a TTY is present but `vitest` in CI runs once; still, be explicit: the `test`
   script MUST be `vitest run` (never bare `vitest`) so it cannot hang. Playwright e2e goes under a
   **separate** `test:e2e` script — it needs a browser download and a running server, which must not
   be forced into the fast unit-test lane.
2. **Playwright smoke is real but isolated.** Add `playwright.config.ts` + one smoke spec that loads
   the shell and asserts a visible element. It runs via `pnpm test:e2e`. In CI it needs a Chromium
   install and a served build — handle that as a dedicated step (see CI wiring), not inside
   `pnpm test`.
3. **ESLint flat config + Prettier, no conflicts.** Vite's `react-ts` template ships an
   `eslint.config.js` (flat config, typescript-eslint). Add Prettier and `eslint-config-prettier`
   (turns off ESLint's formatting rules so ESLint and Prettier don't fight). `pnpm lint` = `eslint .`;
   `pnpm format` = `prettier --write .`; optionally add `format:check` = `prettier --check .`.
4. **Strict TypeScript.** The Vite `react-ts` template already sets `"strict": true`. Keep it and
   additionally ensure `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch` are on
   (template usually includes these in `tsconfig.app.json`). Do not loosen anything.
5. **Routing = `react-router-dom`** with a shared layout (MUI `AppBar` + nav) and three placeholder
   route pages. This is the "routing placeholder for the three surfaces."
6. **Node/pnpm parity with CI:** target node 22, pnpm 10.33.0; set `"engines"` optionally, set
   `packageManager` definitely.

## Ordered steps

Run all commands from `frontend/` unless noted. Create the dir first (`mkdir frontend`).

### 1. Scaffold the Vite react-ts app
- `pnpm create vite@latest . --template react-ts` inside `frontend/` (scaffold into the current dir).
  This yields `package.json`, `index.html`, `src/main.tsx`, `src/App.tsx`, `vite.config.ts`,
  `tsconfig.json` / `tsconfig.app.json` / `tsconfig.node.json`, `eslint.config.js`.
- `pnpm install` to generate `pnpm-lock.yaml`.
- Set `"packageManager": "pnpm@10.33.0"` in `package.json`.

### 2. Add dependencies
- Runtime: `pnpm add @mui/material @emotion/react @emotion/styled react-router-dom`
  (optionally `@mui/icons-material`).
- Dev/test: `pnpm add -D vitest @testing-library/react @testing-library/jest-dom jsdom
  @vitejs/plugin-react` (plugin already present from template), `prettier eslint-config-prettier`,
  and `@playwright/test`.

### 3. Wire scripts in `package.json`
```jsonc
"scripts": {
  "dev": "vite",
  "build": "tsc -b && vite build",        // template default; keep the type-check-then-build
  "preview": "vite preview",
  "lint": "eslint .",
  "format": "prettier --write .",
  "format:check": "prettier --check .",
  "test": "vitest run",                    // MUST be `run`, never bare `vitest`
  "test:e2e": "playwright test"
}
```
- Confirm `build` keeps the template's `tsc -b && vite build` so type errors fail the build (strict).

### 4. ESLint + Prettier config
- Add `eslint-config-prettier` to the flat `eslint.config.js` config array **last** so it disables
  formatting rules. (Import `eslintConfigPrettier` and append it.)
- Add `.prettierrc` (e.g. `{ "singleQuote": true, "semi": true, "trailingComma": "all" }`) and
  `.prettierignore` (`dist`, `pnpm-lock.yaml`, `playwright-report`, `test-results`, `coverage`).
- Run `pnpm format` once so the tree is Prettier-clean, then `pnpm lint` must pass.

### 5. Vitest config
- Add a `test` block to `vite.config.ts` (Vitest reads Vite config):
  `test: { environment: 'jsdom', globals: true, setupFiles: './src/test/setup.ts',
  exclude: [...configDefaults.exclude, 'e2e/**'] }` — **the `e2e/**` exclude is critical** so Vitest
  never tries to run Playwright specs.
- Create `src/test/setup.ts` importing `@testing-library/jest-dom`.
- Add the `vitest/globals` (or `vitest`) types to `tsconfig.app.json` `compilerOptions.types` so
  `describe/it/expect` typecheck under strict mode.

### 6. App shell + routing
- `src/theme.ts` — a minimal MUI `createTheme()` (default palette is fine; note the shared-theme
  future in the README).
- `src/main.tsx` — wrap `<App/>` in `ThemeProvider` + `CssBaseline` + `BrowserRouter`.
- `src/App.tsx` — `<Routes>` with a shared `<Layout/>` (MUI `AppBar` + nav links to the three
  routes) and the three placeholder pages under `src/pages/` (`Console.tsx`, `Ops.tsx`, `Portal.tsx`).
  `/` → redirect to `/console` (or a small index page).
- Delete template cruft not used (the demo counter, `App.css`/logo assets) so `pnpm lint` stays clean
  (unused-vars under strict rules).

### 7. One unit test (proves the `test` lane)
- `src/App.test.tsx` — render the app at `/console` (wrap in `MemoryRouter`) and assert the
  Processing-Agent Console title renders. Keep it a single, fast, deterministic test.

### 8. Playwright smoke
- `pnpm exec playwright install chromium` locally (browsers are gitignored — not committed).
- `playwright.config.ts`:
  - `testDir: './e2e'`
  - `webServer: { command: 'pnpm preview --port 4173', url: 'http://localhost:4173',
    reuseExistingServer: !process.env.CI }` — Playwright auto-starts the preview server (requires a
    prior `pnpm build`; the config's `webServer` handles start/stop).
  - `use: { baseURL: 'http://localhost:4173' }`
  - `projects: [{ name: 'chromium', use: devices['Desktop Chrome'] }]`
- `e2e/smoke.spec.ts` — `page.goto('/')`, assert the shell nav / a surface heading is visible.
- Verify locally: `pnpm build && pnpm test:e2e` → 1 passed.

### 9. `frontend/README.md`
- Short: how to `pnpm install`, `pnpm dev`, `pnpm test`, `pnpm test:e2e`, `pnpm build`.
- One-line note: **Sprint 1 splits this single app into per-surface apps
  (`agent-console`, `ops-dashboard`, `provider-portal`, `timewarp`) + a shared UI/domain package;
  see `wiki/bridge-frontend.md`.** Note the wire is snake_case → camelCase in a future `domain/`
  layer (lessons-learned §B3) — not implemented here.

### 10. CI wiring (`.github/workflows/ci.yml`)
- The existing `frontend` job (lines 85–103) already runs `pnpm install --frozen-lockfile` →
  `pnpm lint` → `pnpm test` → `pnpm build`. After this task those pass as-is. **No change needed for
  lint/test/build to go green.**
- **Add the Playwright smoke to CI** (task item: "one smoke e2e"): insert two steps **after**
  `pnpm build`:
  ```yaml
      - run: pnpm exec playwright install --with-deps chromium
      - run: pnpm test:e2e
  ```
  `--with-deps` installs the OS libs Chromium needs on `ubuntu-latest`. The `webServer` block starts
  `pnpm preview` against the built `dist/` (build already ran). Keep the pinned-SHA action style used
  elsewhere in the file (no new actions are introduced — these are `run:` steps).
- If, during execution, the browser install proves too slow/flaky for the Sprint-0 gate, the
  fallback is to keep `pnpm test:e2e` **local-only** and leave a `# TODO(S1): run e2e in CI` — but
  prefer wiring it, since the task explicitly asks for a smoke and "empty suite ok" means the bar is
  low, not absent.

### 11. Verify locally (all must be green)
- `pnpm install` (clean), `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm build && pnpm test:e2e`.
- Confirm `pnpm-lock.yaml` is committed and `pnpm install --frozen-lockfile` succeeds (simulates CI).

## Gotchas recap

- **`pnpm test` MUST be `vitest run`** — a bare `vitest` watches and hangs CI. Playwright is a
  **separate** `test:e2e` script, never inside `pnpm test`.
- **Exclude `e2e/**` from Vitest** (`test.exclude`) or Vitest tries to execute Playwright specs and
  fails.
- **Commit `pnpm-lock.yaml`** — CI's `--frozen-lockfile` fails on a missing/stale lock.
- **`eslint-config-prettier` goes LAST** in the flat config so it disables conflicting formatting
  rules; otherwise `pnpm lint` and `pnpm format` fight.
- **Playwright browsers are gitignored / not committed** — CI must `playwright install --with-deps
  chromium`; locally run `pnpm exec playwright install chromium` before `pnpm test:e2e`.
- **Playwright `webServer` needs a built app** (`pnpm preview` serves `dist/`); run `pnpm build`
  before `pnpm test:e2e`. In CI the build step already precedes it.
- **Single app, not a workspace** — keeping `package.json` at `frontend/` root is what the S0.1 CI
  job assumes; do not introduce a pnpm workspace in Sprint 0.
- **Keep it a shell** — Sprint 0 ships no domain behavior; no SSE, no wire mapping, no data.
