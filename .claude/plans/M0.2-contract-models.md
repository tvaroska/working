**Depends on:** M0.1 (done — `agents/` uv project + src layout exist). **Feeds:** M0.3 (`BridgeClient` port consumes these), M0.4 (mock loads eval → these), M0.6 (round-trip test asserts against these).

## Goal (scope of THIS task only)

Define the **Pydantic domain contract** the whole agent↔Bridge exchange travels as: `CollectRequest` (in),
`ExchangeTurn` carrying `CollectionStatus` (out), `LedgerEntry` (one classified doc), and the extraction
`fields` shape. These types are **the artifact under validation** in Milestone 0 — the point of M0 is to prove
this shape is right before real logic is built on it. Field names **mirror `wiki/evals/address/expected.json`**
so eval data validates cleanly into the models.

**Explicitly NOT in this task** (later M0 tasks / Sprint 1):
- No `BridgeClient` port, no `a2a-sdk` client/server, no A2A part/artifact (de)serialization — that is M0.3/M0.4.
- No disposition/gate **logic**, no `run_disposition_gate`, no `is_satisfied`, no canonicalization — Sprint 1.
  The models carry a `disposition` value (the mock hardcodes one); they do not compute it.
- No agent, no mock server, no README.

## Context an executor needs (do not re-derive)

### Where the shape comes from
- **`wiki/bridge-a2a-edge.md`** is authoritative on the outbound shape: *"The deliverable to the servicer's agent
  is an `ExchangeTurn` carrying a `CollectionStatus` — the classified ledger: a tuple of `LedgerEntry`
  (doctype · disposition · canonical issuer · key fields), plus a best-effort 'still outstanding' and a
  `terminal` flag."* Domain types travel **inside** A2A parts/artifacts; the domain contract is unchanged, the
  envelope is standard.
- **`wiki/bridge-aggregate-model.md`**: exchange = the A2A **context** (1:1, no separate exchange ID); **party** =
  a stable counterparty reference (not a Bridge aggregate). So `CollectRequest` names a `party` + a process
  `skill`, and the turn names a `context_id`.
- **`wiki/evals/address/expected.json`** is the field-name source of truth (read it in full before coding). Each
  entry has: `id`, `doctype`, `issuer_raw`, `issuer`, `expected_disposition`, `expected_gate`, and an
  `extraction` block: `{ fields: {doctype, issuer?, key_fields:{...}}, overall_confidence, field_confidence,
  legible, flagged_fields }`. Note `issuer` is the **canonical** value (`power-co`), `issuer_raw` is the raw
  (`PowerCo` / `Power Co.`); canonicalization logic is Sprint 1, but the canonical field exists in the shape now.
- Enum vocab observed in the eval: **disposition** ∈ `{accepted, pending, rejected}`; **gate** ∈
  `{auto_approve, hitl_review, resubmit, unsupported}` (gate is disposition-internal, **out of M0 scope** — do
  not model it).
- `key_fields` differs by doctype (gov-id: `name, address, doc_number, issuing_authority, expiry`; utility-bill:
  `name, service_address, statement_date`). Do **not** pin per-doctype field schemas in M0 — model `key_fields`
  as an open `dict[str, str]`. Typed per-doctype validation is a Sprint-1 concern.

### Package / import discipline (invariants — honor these)
- Models live in **`agents/src/contract/`**, importable as `contract` (src layout; hatchling wheel target already
  declares `src/contract`). The existing `agents/src/contract/__init__.py` holds only a module docstring.
- **`contract` must not import `agents`** (nor anything under it). The `BridgeClient` port (M0.3) will depend on
  `contract` **only**, so the mock→real swap is invisible to the agent. Keep `contract` dependency-free except
  for stdlib + pydantic. (This mirrors the repo's `bridge/` never imports `agents/` discipline.)
- Python is **3.12**: use `enum.StrEnum` for the disposition enum (clean JSON round-trip, forward-compatible for
  Sprint 1) and `X | None` union syntax.

### Seams touched
**None.** M0.2 is pure domain types — no managed-service boundary, so no local+GCP adapter pair applies. The
seam/adapter discipline begins at M0.3 (`BridgeClient` port) / M0.4 (mock server). Just keep `contract` free of
transport/agent imports so those seams can layer on cleanly.

## The models to define (single module `agents/src/contract/models.py`)

Put all models in one module `models.py` and re-export them from `contract/__init__.py` (so `from contract import
CollectRequest, ExchangeTurn, ...` works — this is what M0.3–M0.6 will import). Give every model
`model_config = ConfigDict(extra="forbid")` **except** `ExtractedFields` (see note) so contract drift fails loud.

1. **`Disposition(StrEnum)`** — `ACCEPTED = "accepted"`, `PENDING = "pending"`, `REJECTED = "rejected"`.
   (String values mirror the eval's `expected_disposition`.)

2. **`ExtractedFields(BaseModel)`** — the `extraction.fields` block. Fields:
   - `doctype: str`
   - `issuer: str | None = None`  (canonical issuer; absent for gov-id)
   - `key_fields: dict[str, str] = Field(default_factory=dict)`
   - **Config exception:** use `extra="ignore"` here (not forbid) OR keep `forbid` — decision: keep **`forbid`**;
     the eval `fields` block contains exactly these three keys, so forbid still validates cleanly and catches typos.

3. **`Extraction(BaseModel)`** — the full `extraction` block, so the eval payload round-trips through the A2A
   envelope in M0.6. Fields (mirror eval names exactly):
   - `fields: ExtractedFields`
   - `overall_confidence: float | None = None`
   - `field_confidence: dict[str, float] = Field(default_factory=dict)`
   - `legible: bool | None = None`
   - `flagged_fields: list[str] = Field(default_factory=list)`
   - **Decision to record:** the confidence/legible/flagged signals are carried but **not acted on** in M0
     (disposition is Sprint 1). They are included anyway because the task says "field names mirror expected.json"
     and because carrying them lets the round-trip test assert the eval payload survived the standard A2A envelope
     intact. They are all optional/defaulted so a minimal producer need not set them.
   - This means `Extraction.model_validate(entry["extraction"])` from a raw eval entry **just works** — that is the
     whole point of mirroring, and the mock (M0.4) relies on it.

4. **`LedgerEntry(BaseModel)`** — one classified document in the ledger (doctype · disposition · canonical issuer ·
   key fields + id). Fields:
   - `id: str`
   - `doctype: str`
   - `issuer: str | None = None`  (canonical)
   - `disposition: Disposition`
   - `extraction: Extraction`
   - **Note:** the *raw top-level* eval entry has extra keys (`issuer_raw`, `expected_disposition`,
     `expected_gate`, `artifact`, `synthetic`, `note`), so `LedgerEntry.model_validate(raw_entry)` will **fail**
     under `extra="forbid"` — that is intended. M0.4 constructs `LedgerEntry` explicitly, mapping
     `expected_disposition → disposition` and building `extraction` via `Extraction.model_validate(...)`. Record
     this so M0.4's author does not try to validate the whole raw entry.
   - `artifact` reference (`FileWithUri` handle from bridge-a2a-edge) is **Sprint 1+** — do NOT add it in M0.

5. **`CollectionStatus(BaseModel)`** — the classified ledger container. Fields:
   - `ledger: list[LedgerEntry] = Field(default_factory=list)`
   - `outstanding: list[str] = Field(default_factory=list)`  (best-effort "still outstanding" refs)
   - `terminal: bool = False`
   - (In M0 the mock returns one accepted entry, `outstanding=[]`, `terminal=True`.)

6. **`ExchangeTurn(BaseModel)`** — what the Bridge returns to the agent (the outbound envelope's domain payload).
   Fields:
   - `context_id: str`  (the A2A context = exchange, echoed back so both sides name the interaction identically)
   - `status: CollectionStatus`

7. **`CollectRequest(BaseModel)`** — what the agent sends. Fields:
   - `party: str`  (stable counterparty reference, e.g. `"jordan-lee"`)
   - `skill: str`  (the process skill requested, e.g. `"address-proof"`)
   - `context_id: str | None = None`  (None = mint a new exchange/context; set = continue one)
   - Keep it this minimal — no requirements list / doctype slots (that is Sprint 1's Collect loop). Record: the
     single `address-proof` request for `jordan-lee` is what M0.5 will build.

### `contract/__init__.py` re-exports
Replace the bare docstring file with the docstring **plus** imports from `.models` and an `__all__` listing all
seven public names (`Disposition`, `ExtractedFields`, `Extraction`, `LedgerEntry`, `CollectionStatus`,
`ExchangeTurn`, `CollectRequest`). Keep the existing module docstring text.

## Tests to add (`agents/tests/test_contract.py`)

1. **Construct + JSON round-trip:** build a full `ExchangeTurn` (with one `LedgerEntry`) in code; assert
   `ExchangeTurn.model_validate_json(turn.model_dump_json()) == turn`. Proves the payload is JSON-serializable
   (M0.3/M0.4 put it inside A2A parts as JSON).
2. **Eval mirror (the load-bearing test):** load the real `wiki/evals/address/expected.json`; for **every**
   entry, assert `Extraction.model_validate(entry["extraction"])` succeeds. Spot-check `gov-id-clean`:
   `ex.fields.doctype == "gov-id"`, `ex.fields.key_fields["name"] == "Jordan Lee"`, `ex.overall_confidence == 0.96`.
   This guards the "field names mirror expected.json" invariant and fails loudly if the eval or the model drift.
3. **LedgerEntry from eval entry (explicit mapping):** build a `LedgerEntry` from the `gov-id-clean` raw entry by
   mapping `expected_disposition → Disposition` + `Extraction.model_validate(entry["extraction"])`; assert
   `entry.disposition is Disposition.ACCEPTED` and `entry.id == "gov-id-clean"`. Documents the M0.4 mapping path.
4. **`extra="forbid"` bites:** assert `LedgerEntry.model_validate(raw_gov_id_clean_entry)` raises
   `pydantic.ValidationError` (proves the whole raw entry is NOT a LedgerEntry — extra keys rejected — so M0.4
   must map explicitly). Optionally assert an unknown field on `CollectRequest` also raises.
5. **CollectRequest defaults:** `CollectRequest(party="jordan-lee", skill="address-proof").context_id is None`.

## Gotchas recap

- **`contract` stays import-clean** — no `agents` import, only stdlib + pydantic; the port depends on it alone.
- **`extra="forbid"`** means a raw eval *entry* is not a `LedgerEntry` (it has `artifact`/`note`/`expected_*`); the
  `extraction` sub-block **is** a valid `Extraction`. M0.4 maps the entry explicitly — don't validate the whole raw
  entry.
- **Mirror the eval names exactly** (`key_fields`, `overall_confidence`, `field_confidence`, `legible`,
  `flagged_fields`, `issuer`) — the whole M0 validation rests on eval data flowing through unchanged.
- **`issuer` is canonical, `issuer_raw` is not modeled** in M0 (canonicalization is Sprint 1); include only the
  canonical `issuer` field.
- Disposition/gate **values** exist in the shape, but no disposition/gate **logic** here — the mock hardcodes an
  accepted entry. Do not import or invent `run_disposition_gate` / gates.
- Run all `uv`/`pytest`/`ruff` from inside `agents/` (project root is `agents/`, not repo root).
