# S0.1 — CI pipeline (GitHub Actions)

**Sprint:** 0 (scaffolding) · **Task line:** `PLAN.md` S0.1
**Goal:** One workflow, path-filtered per project, that is the **green merge gate** for the whole
repo. Jobs: **agents**, **core** (`bridge/`), **skills**, **frontend** — each guarded so a
not-yet-existing project no-ops instead of failing, and a single aggregation check that branch
protection points at.

## Design decisions (baked in — don't re-litigate)

1. **Change detection = `dorny/paths-filter`** in one `changes` job that emits per-project booleans;
   downstream jobs gate on both the filter output **and** `hashFiles(...)` existence of the project's
   manifest. This is what makes docs-only PRs skip code jobs *and* makes not-yet-scaffolded projects
   no-op — one mechanism, two payoffs.
2. **Single required status check = a final `ci-success` aggregation job.** Branch protection points at
   `ci-success` only. Skipped project jobs (path-filtered out or not-yet-existing) must **not** block the
   merge — the aggregation job treats `skipped`/`success` as pass and only fails on real `failure`/
   `cancelled`. This is the standard fix for "required check never runs because it was path-filtered."
3. **Pin all third-party actions to a full commit SHA** with a trailing `# vX.Y.Z` comment (supply-chain
   hygiene; the workflow itself is a merge gate). Pin `astral-sh/setup-uv`, `dorny/paths-filter`,
   `actions/checkout`, `pnpm/action-setup`, `actions/setup-node`.
4. **Let uv own the Python interpreter.** `astral-sh/setup-uv` reads each project's `.python-version`
   (job `working-directory` = the project dir) and `uv sync` installs CPython 3.12. Do **not** add
   `actions/setup-python` — one source of truth for the interpreter.
5. **Lockfile drift is a hard error.** Use `uv sync --locked` (fails if `uv.lock` is stale vs.
   `pyproject.toml`) and `pnpm install --frozen-lockfile`. This is half of the "SDK-pin drift guard";
   the other half is `test_scaffold.py` (see below).
6. **SDK-pin drift surfaced as its own step.** Run `uv run pytest tests/test_scaffold.py` as a dedicated,
   clearly-named step **before** the full suite so a pin drift out of `google-adk>=2.7.0,<3` shows up as
   a distinctly-labeled red step, not buried in 49 tests (PLAN.md S0.1 item 4 / ADR-0001 SDK risk).
7. **`bridge/` isolation guard runs in the core job.** PLAN.md S0.1 item 3 + S0.2 item 3: the
   `bridge/tests/test_no_agents_import.py` guard runs as part of the core job's normal `uv run pytest`
   (no special wiring needed — it's just a test in that suite). Note it here so the executor doesn't add
   a redundant step.
8. **`concurrency`** group per-ref with `cancel-in-progress: true` so pushes supersede stale runs.

## Ordered steps

### 1. Create `.github/workflows/ci.yml`

Header:

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
permissions:
  contents: read
```

### 2. `changes` job — path filter (docs-only skip)

Uses `dorny/paths-filter`. Outputs one boolean per project. Suggested filters:

```yaml
jobs:
  changes:
    runs-on: ubuntu-latest
    outputs:
      agents:   ${{ steps.filter.outputs.agents }}
      core:     ${{ steps.filter.outputs.core }}
      skills:   ${{ steps.filter.outputs.skills }}
      frontend: ${{ steps.filter.outputs.frontend }}
    steps:
      - uses: actions/checkout@<sha>   # v4
      - uses: dorny/paths-filter@<sha> # v3
        id: filter
        with:
          filters: |
            agents:
              - 'agents/**'
              - '.github/workflows/ci.yml'
            core:
              - 'bridge/**'
              - '.github/workflows/ci.yml'
            skills:
              - 'skills/**'
              - '.github/workflows/ci.yml'
            frontend:
              - 'frontend/**'
              - '.github/workflows/ci.yml'
```

Including the workflow file itself in every filter means edits to CI re-run all jobs (safe default).
Docs-only PRs (`wiki/**`, `docs/**`, `*.md`, `PLAN.md`) match nothing → all code jobs skip → `ci-success`
still passes.

### 3. `agents` job

```yaml
  agents:
    needs: changes
    if: needs.changes.outputs.agents == 'true'
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: agents
    steps:
      - uses: actions/checkout@<sha>
      - uses: astral-sh/setup-uv@<sha>   # v6
        with:
          enable-cache: true
          cache-dependency-glob: 'agents/uv.lock'
      - run: uv sync --locked
      - run: uv run ruff check .
      - name: SDK pin drift guard (test_scaffold.py)
        run: uv run pytest tests/test_scaffold.py
      - run: uv run pytest
```

Notes: `working-directory: agents` makes setup-uv read `agents/.python-version` and installs 3.12;
`uv sync` builds `.venv` and installs the project editable. The full `uv run pytest` re-runs
`test_scaffold.py` — harmless duplication, keeps the pin-guard step isolated for a clear signal.

### 4. `core` job (`bridge/`)

Mirror the agents job with `working-directory: bridge` and `cache-dependency-glob: 'bridge/uv.lock'`.
**Guard on both the filter and manifest existence** so it no-ops until S0.2 lands `bridge/pyproject.toml`:

```yaml
  core:
    needs: changes
    if: needs.changes.outputs.core == 'true' && hashFiles('bridge/pyproject.toml') != ''
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: bridge
    steps:
      - uses: actions/checkout@<sha>
      - uses: astral-sh/setup-uv@<sha>
        with:
          enable-cache: true
          cache-dependency-glob: 'bridge/uv.lock'
      - run: uv sync --locked
      - run: uv run ruff check .
      - run: uv run pytest    # includes tests/test_no_agents_import.py (isolation guard)
```

> `hashFiles()` is valid in job-level `if:` and returns `''` when no file matches — the clean "project
> not scaffolded yet" guard. Until S0.2, `bridge/pyproject.toml` doesn't exist, `changes.outputs.core`
> is also false, so this job skips and `ci-success` is unaffected.

### 5. `skills` job

Guard on `skills/` existence. `skills-ref` install command is **unresolved (S0.6 owns it)** — leave a
loud TODO and a placeholder so the job is present but doesn't falsely pass/fail:

```yaml
  skills:
    needs: changes
    if: needs.changes.outputs.skills == 'true' && hashFiles('skills/**/SKILL.md') != ''
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<sha>
      # TODO(S0.6): install skills-ref (package/version unresolved in repo docs) and run:
      #   for d in skills/*/; do skills-ref validate "$d" || exit 1; done
      - run: echo "skills job placeholder — wired for real in S0.6"
```

Because the guard requires a `skills/**/SKILL.md`, this whole job stays skipped until S0.6 authors the
`address-proof` skill. The executor should NOT try to invent a `skills-ref` install here — just record
the exact command shape in the comment.

### 6. `frontend` job

Guard on `frontend/package.json`. pnpm via pinned `pnpm/action-setup`, node via `actions/setup-node`
with pnpm cache:

```yaml
  frontend:
    needs: changes
    if: needs.changes.outputs.frontend == 'true' && hashFiles('frontend/package.json') != ''
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@<sha>
      - uses: pnpm/action-setup@<sha>      # v4 (reads packageManager / version)
      - uses: actions/setup-node@<sha>     # v4
        with:
          node-version: '22'
          cache: pnpm
          cache-dependency-path: frontend/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm test
      - run: pnpm build
```

Skips until S0.4 lands `frontend/package.json`. (S0.4 will also add the Playwright smoke; `pnpm test`
runs it or a `playwright` script — confirm the exact script names when S0.4 defines them.)

### 7. `ci-success` aggregation gate (the single required check)

```yaml
  ci-success:
    if: always()
    needs: [changes, agents, core, skills, frontend]
    runs-on: ubuntu-latest
    steps:
      - name: Verify no job failed
        run: |
          results='${{ join(needs.*.result, ' ') }}'
          echo "job results: $results"
          for r in $results; do
            if [ "$r" = "failure" ] || [ "$r" = "cancelled" ]; then
              echo "A required job did not succeed."; exit 1
            fi
          done
          echo "All jobs passed or were skipped."
```

`if: always()` ensures it runs even when upstream jobs skip; it treats `skipped`/`success` as OK and
fails only on real `failure`/`cancelled`. **This is the job name to put in branch protection** (document
that in the PR / S0.7 dev-env doc).

### 8. Verify locally as far as possible

- YAML sanity: `python -c "import yaml,sys; yaml.safe_load(open('.github/workflows/ci.yml'))"` (or
  `uv run --with pyyaml ...`) — CI file must parse.
- Reproduce the agents job locally: `cd agents && uv sync --locked && uv run ruff check . &&
  uv run pytest` → must be green (matches the 49-pass baseline).
- Optionally lint the workflow with `actionlint` if available (not required; note it in the dev-env doc
  as a pre-commit candidate for S0.7).
- If `gh` + a remote are configured, `gh workflow list` / trigger a PR to confirm the run; otherwise the
  workflow is validated on first push.

## Gotchas recap

- **Skipped required checks block merges** unless you use the `ci-success` aggregation pattern — don't
  make the individual project jobs the required checks.
- **`hashFiles()` in `if:`** returns `''` for no match — that's the "not scaffolded yet" guard for
  core/skills/frontend. Combine with the paths-filter output (`&&`).
- **Run uv from inside each project dir** (`working-directory`), not repo root — uv project root is
  `agents/` (and later `bridge/`), each with its own `.python-version` + `uv.lock`.
- **`uv sync --locked`, not `--frozen`** — `--locked` errors on a stale lock (drift guard);
  `--frozen` silently uses the existing lock.
- **No secrets in the agents job** — the suite is fully offline (adk_stub + localhost uvicorn). Adding a
  `GOOGLE_API_KEY` is unnecessary and would be a footgun.
- **`skills-ref` install is unresolved in repo docs** — do not guess a package here; leave the TODO and
  let S0.6 pin it. The guard keeps the job skipped meanwhile so CI stays honest.
- **Pin action SHAs**, not floating tags — the merge gate is security-sensitive.
