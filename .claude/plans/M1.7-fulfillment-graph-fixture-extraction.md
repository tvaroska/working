# M1.7 — Extraction / fulfillment graph (fixture adapter)

**Milestone:** M1 — Bridge Core (local). **Depends on:** M1.1 (seams — `ExtractionSeam`,
`FixtureExtractionEngine` skeleton), M1.6 (disposition — `run_disposition_gate`, `classify_document`,
`Gate`). **Blocks:** M1.8 (edge maps disposition→task-status), M1.10 (A2UI feeds Path-B intake into
this graph), M1.11 (dual-path routing dispatches Path B here).

## Goal (what "done" means)

Two deliverables in `bridge/`:

1. **The fixture extraction engine** — fill in `FixtureExtractionEngine.extract()` (today it raises
   `NotImplementedError("M1.7: ...")`). Deterministic, no Gemini, no network: maps a Path-B
   "document" to a `contract.Extraction`, keyed off the eval fixtures. Plus a thin ADR-0005 engine
   *resolution* shell (only the fixture engine is live in Phase-1 local).

2. **The Path-B fulfillment graph** (`bridge/src/bridge/fulfillment.py`, new) — the durable pipeline
   the Bridge runs when a **human** party uploads a document:
   `receive → extract_with_quality_gate → confidence_gate → {auto_approve | hitl_review | escalate |
   extraction_error}`, with a **resubmission loop ≤ 3** (`resubmit` **non-resumable** — A1) and HITL
   **suspending with zero compute** (resumable phases = `{hitl, escalated}`).

The single hard acceptance: given each of the 8 eval fixtures as a Path-B intake, the graph reaches
the phase/disposition that matches M1.6's gate (auto_approve→accepted terminal, hitl_review→hitl
suspended pending, resubmit→resubmit loop, unsupported→rejected terminal), the resubmission loop
escalates after 3 attempts, `resubmit` refuses a decision-resume, and `{hitl, escalated}` resume to a
final disposition without re-running extraction.

## The load-bearing design decision (do NOT re-derive — honor it)

**The fulfillment graph is a deterministic Python state machine, NOT an `google.adk.workflow.Workflow`.**

Rationale (this is the non-obvious call that de-risks the task):
- The Bridge-core sense-A pipeline is *"code decides"* deterministic logic (extract → gate →
  disposition). Every existing `bridge/` module (`disposition.py`, `ledger.py`, `aggregate.py`,
  `signals.py`) is a pure/deterministic module, not an ADK runtime construct. Match that idiom.
- The quality gate + confidence gate + thresholds are **already** `run_disposition_gate` (M1.6). The
  fulfillment graph must **not** re-implement thresholds — it is a thin router over the returned
  `Gate` plus loop/suspend/attempt state. (Single-source the gate; duplicating it breaks parity.)
- The *durable-graph-with-suspend/resume* mechanism was already proven on the **consumer** side in
  S1-6 (`google.adk.workflow.Workflow` + `DatabaseSessionService` + `ResumabilityConfig`, see
  `agents/src/agents/address/graph.py`, `PLAN.md` S1-6). Re-proving it inside `bridge/` is redundant
  and out of proportion for this task. M1.7 depends only on M1.1 + M1.6 — **not** M1.2 stores /
  sessions — which confirms it is not meant to wire an ADK runtime.
- "Durable" and "zero compute while suspended" are naturally satisfied by a pure state machine: it
  returns a *suspended* result and nobody calls it again until an event (human decision, or a fresh
  document) arrives. Its state is designed **JSON-serializable** so the M1.8/M1.11 edge can carry it
  on the durable task (parity with how M1.4 stamps `LedgerEntry` on `task.metadata` via
  `bridge.ledger.stamp_ledger_entry`) — but the carry/wiring is the edge's job, out of M1.7 scope.
- ADK-native binding of the suspend points (HITL as `LongRunningFunctionTool`, uploads as versioned
  ADK artifacts, resume via webhook — platform bet 1, `wiki/bridge-fulfillment-graph.md`) happens at
  the **edge** (M1.8/M1.10/M1.11), not in this deterministic core.

Add a module docstring paragraph stating this explicitly so a future reader does not "upgrade" it to
a Workflow.

## Background facts (verified — do not re-derive)

- **Gate → fulfillment outcome mapping** (M1.6 `Gate` is the input; see `bridge/src/bridge/disposition.py`):
  | M1.6 Gate | fulfillment phase | disposition | terminal? | resumable? |
  |---|---|---|---|---|
  | `auto_approve` | `AUTO_APPROVE` | accepted | yes | n/a |
  | `hitl_review` | `HITL` | pending | no (suspended) | **yes** |
  | `resubmit` | `RESUBMIT` (loop) or `ESCALATED` when exhausted | rejected (this attempt) / pending (escalated) | no | resubmit=**no**, escalated=**yes** |
  | `unsupported` | `UNSUPPORTED` | rejected | yes | n/a |
  | *(engine raised `ExtractionError`)* | `EXTRACTION_ERROR` | pending | yes | no |

- **The quality gate and confidence gate are fused inside `run_disposition_gate` already** (M1.6
  algorithm: type_match → quality[legible/<0.55] → confidence[≥0.85 & no flags] → hitl). The graph
  calls `classify_document(doc_id, extraction, thresholds=...)` **once** → `(LedgerEntry,
  DispositionResult)` and routes on `result.gate`. Do NOT read thresholds or re-derive routing here.

- **Resubmission loop ≤ 3, then escalate — exact semantics (A1).** `attempts` = number of resubmissions
  requested so far (initial extraction is attempt 0). On a `RESUBMIT` gate: if `attempts <
  max_resubmissions` → `attempts += 1`, phase `RESUBMIT` (await a *fresh document*); else (a
  `RESUBMIT` verdict when `attempts == max_resubmissions`) → phase `ESCALATED`. Worked example with
  `max_resubmissions=3`: initial blurry → resubmit(attempts=1); resubmit #1 blurry →
  resubmit(attempts=2); #2 blurry → resubmit(attempts=3); #3 blurry → **escalated**. So the party
  gets 3 resubmission requests; the 4th failure escalates.

- **`max_resubmissions` comes from the skill policy, not a literal.** `SkillPolicy.max_resubmissions`
  (default 3) is already in `bridge/src/bridge/skills.py`, loaded from
  `skills/address-proof/assets/policy.yaml` (`retry.max_resubmissions: 3`) by `LocalSkillRegistry`
  (M1.3). Read it from the policy; default the function arg to 3 so it resolves standalone.

- **A1 — the resumable/non-resumable split is the correctness heart.** `RESUMABLE_PHASES =
  frozenset({Phase.HITL, Phase.ESCALATED})`. `resubmit` is **not** resumable: it awaits a *fresh
  document*, not a human decision. Escalation ≠ rejection: escalated disposition is `PENDING` ("the
  doc was never judged wrong, we just gave up reading it"), NOT rejected. Collapsing "can't read it"
  into "rejected" is the bug A1 warns against.

- **`unsupported` (passport) is a terminal reject** in the graph. The `wiki/bridge-fulfillment-graph.md`
  diagram has no `unsupported` leaf, but M1.6 emits `Gate.UNSUPPORTED` for passport; route it to a
  terminal rejected phase (distinct from `EXTRACTION_ERROR`, which is an *engine failure*, not a
  doctype judgment).

- **`extraction_error` = the engine raised**, distinct from `escalate` (loop exhaustion). Model an
  `ExtractionError` exception the fixture engine raises for an unknown/failing document; the graph
  catches it → phase `EXTRACTION_ERROR`, disposition `PENDING` (engine failure, not a judgment),
  terminal + non-resumable (operator/engine intervention is out of Phase-1 scope). Flag this
  disposition choice in the plan; the design owner can revisit.

- **The fixture engine input ("document").** The `ExtractionSeam.extract(document, doctype_skill)`
  signature left both as `object` (M1.1). The **fixture** engine concretizes `document` as a small
  value object `FixtureDocument(fixture_id: str, extraction: Extraction | None = None, fail: bool =
  False)` — a Path-B intake keyed to a deterministic eval fixture. Look up `fixture_id` in
  `wiki/evals/address/expected.json`; return `Extraction.model_validate(doc["extraction"])`. `fail=True`
  or an unknown `fixture_id` → raise `ExtractionError` (drives the `extraction_error` path in tests).
  The graph stays **engine-agnostic** — it passes `document` straight through to `engine.extract`; only
  the fixture adapter and its tests know about `FixtureDocument`.

- **ADR-0005 engine resolution (keep minimal).** M1.6's plan noted "M1.7 implements the fixture engine
  + engine resolution." For Phase-1 local, only the fixture engine is live. Ship a small
  `resolve_extraction_engine(doctype_skill=None, *, mode="fixture") -> ExtractionSeam` that returns
  `FixtureExtractionEngine()` for `mode="fixture"`; leave `gemini`/`docai` branches as
  `NotImplementedError("Sprint 2 / Phase 4")` with a docstring citing the ADR-0005 resolution order
  (config mode → per-doctype capability → Gemini fallback). Do **not** over-build multi-engine
  resolution — one engine is live; the branch structure documents the seam.

- **Eval path resolution without importing `agents`.** Reuse the walk-up pattern already in
  `bridge/tests/test_disposition.py::TestGateParity.resolve_evals_path` and
  `bridge/src/bridge/skills.py::resolve_default_skills_dir` (walk ancestors for
  `wiki/evals/address/expected.json`; honor `ADDRESS_EVALS_PATH` env override for parity with the mock
  `agents/src/agents/mock_bridge/fixtures.py`). Do **not** import the mock's `fixtures.py` — reimplement
  a tiny loader in the fixture adapter (`bridge/` never imports `agents/`).

## Files to create

### 1. `bridge/src/bridge/fulfillment.py` (new) — the Path-B graph
- Module docstring: the graph shape; the "deterministic state machine, NOT a `Workflow`" decision
  (see above) with the S1-6 pointer; cite `wiki/bridge-fulfillment-graph.md`, ADR-0005 (extraction is
  a seam), lessons A1 (resubmit non-resumable / escalation ≠ rejection); note it's kept out of
  `__init__.py` and imports no `agents`.
- `class Phase(StrEnum)`: `AUTO_APPROVE = "auto_approve"`, `HITL = "hitl"`, `RESUBMIT = "resubmit"`,
  `ESCALATED = "escalated"`, `EXTRACTION_ERROR = "extraction_error"`, `UNSUPPORTED = "unsupported"`.
  (Values chosen to read cleanly in the read-model; `hitl`/`escalated` match A1's `phase=` vocabulary.)
- `RESUMABLE_PHASES: frozenset[Phase] = frozenset({Phase.HITL, Phase.ESCALATED})` — cite A1.
- `TERMINAL_PHASES: frozenset[Phase] = frozenset({Phase.AUTO_APPROVE, Phase.UNSUPPORTED,
  Phase.EXTRACTION_ERROR})` (escalated/hitl are suspended-not-terminal; resubmit is awaiting).
- `class FulfillmentResult(BaseModel, frozen=True)` (`extra="forbid"`), JSON-serializable durable
  state (so the M1.8/M1.11 edge can stamp it on a task):
  - `phase: Phase`
  - `disposition: Disposition | None` (None only mid-loop if you prefer; but set it per the mapping —
    accepted/pending/rejected)
  - `attempts: int = 0` (resubmissions requested so far)
  - `entry: LedgerEntry | None = None` (the classified doc; None only on `EXTRACTION_ERROR` where no
    extraction was produced)
  - `suspended: bool` (True iff `phase in RESUMABLE_PHASES`)
  - `terminal: bool` (True iff `phase in TERMINAL_PHASES`)
  - `awaiting_resubmission: bool` (True iff `phase == Phase.RESUBMIT`)
  - helper `@property resumable` or rely on `suspended` — keep it explicit and derived at construction.
- `async def run_fulfillment(document: object, doctype_skill: object = None, *, engine:
  ExtractionSeam, thresholds: DispositionThresholds = DispositionThresholds(), max_resubmissions: int
  = 3, doc_id: str | None = None, attempts: int = 0) -> FulfillmentResult`:
  1. **receive** — accept `document`.
  2. **extract_with_quality_gate** — `try: extraction = await engine.extract(document, doctype_skill)`
     `except ExtractionError:` → return `FulfillmentResult(phase=EXTRACTION_ERROR,
     disposition=PENDING, attempts=attempts, entry=None, terminal=True, suspended=False,
     awaiting_resubmission=False)`.
  3. `entry, result = classify_document(doc_id or <derive>, extraction, thresholds=thresholds)`.
     (Derive `doc_id` from `getattr(document, "fixture_id", "doc")` when None, or require it — pick
     one and document it. Simplest: `doc_id or getattr(document, "fixture_id", None) or "doc"`.)
  4. **route on `result.gate`** per the mapping table:
     - `AUTO_APPROVE` → phase AUTO_APPROVE, accepted, terminal.
     - `HITL_REVIEW` → phase HITL, pending, suspended.
     - `UNSUPPORTED` → phase UNSUPPORTED, rejected, terminal.
     - `RESUBMIT` → if `attempts < max_resubmissions`: phase RESUBMIT, rejected (this attempt),
       `attempts+1`, `awaiting_resubmission=True`; else: phase ESCALATED, **pending** (A1: escalation
       ≠ rejection), suspended.
  5. return the populated `FulfillmentResult` (set `suspended`/`terminal`/`awaiting_resubmission`
     consistently from the phase; assert `entry` is carried for every non-error branch).
- `def resume_fulfillment(state: FulfillmentResult, *, accept: bool) -> FulfillmentResult`:
  - Guard: `if state.phase not in RESUMABLE_PHASES: raise ValueError(...)` — this enforces A1
    (`resubmit`/terminal phases cannot be decision-resumed). Message must name the phase and say
    resubmit awaits a fresh document, not a decision.
  - Resolve the human decision: `accept=True` → new state phase AUTO_APPROVE, disposition ACCEPTED,
    terminal, with the same `entry` (its `disposition` updated to accepted); `accept=False` → phase
    UNSUPPORTED? No — a HITL/escalated **reject** is a genuine rejection → disposition REJECTED,
    terminal. Choose a terminal phase for a human reject: reuse `Phase.UNSUPPORTED`? That conflates
    doctype-unsupported with human-reject. **Add a distinct terminal phase** `REJECTED = "rejected"`
    for human/escalation rejects, OR carry the disposition and leave phase as a terminal marker.
    **Decision: add `Phase.REJECTED = "rejected"`** to the enum + `TERMINAL_PHASES`; use it for a
    human reject on resume. (Update the enum list above accordingly.)
  - Pure/sync (no I/O) — this is the "zero compute while suspended, resume feeds a decision" step;
    it must **not** call the engine (assert in tests via a spy engine).
- `def submit_resubmission(...)` — **not a new function**; a resubmission is simply calling
  `run_fulfillment(new_document, ..., attempts=prior_state.attempts)` again. Document this in the
  module docstring / `run_fulfillment` docstring so the caller (M1.11) threads `attempts` forward. The
  non-resumability of `resubmit` is exactly this: no decision-resume path exists; only a fresh
  `run_fulfillment` with a new document and the carried `attempts`.
- `__all__` exporting `Phase`, `RESUMABLE_PHASES`, `TERMINAL_PHASES`, `FulfillmentResult`,
  `run_fulfillment`, `resume_fulfillment`.

## Acceptance criteria
1. `FixtureExtractionEngine.extract` deterministically returns the eval-sourced `Extraction` for each
   of the 8 fixtures; unknown/`fail` → `ExtractionError`. No Gemini, no network.
2. The fulfillment graph reaches the correct phase + disposition for every fixture, matching M1.6's
   gate (auto_approve→accepted terminal; hitl_review→hitl suspended pending; resubmit→resubmit loop;
   unsupported→rejected terminal).
3. Resubmission loop is **≤ 3** (from `SkillPolicy.max_resubmissions`), then **escalates**; escalated
   disposition is **PENDING** (escalation ≠ rejection — A1).
4. `resubmit` is **non-resumable** (decision-resume raises); `{hitl, escalated}` are resumable and
   resume with **zero compute** (engine not re-called).
5. Extraction is exercised **through the seam** (`ExtractionSeam`); the graph is engine-agnostic
   (receives the engine by parameter, imports no adapter).
6. The graph is a **deterministic state machine, not an ADK `Workflow`**; its `FulfillmentResult` is
   JSON-serializable for the M1.8/M1.11 durable-task carry.
7. Import discipline holds: `bridge/` imports no `agents/`; new modules absent from `bridge/__init__.py`;
   `test_no_agents_import.py` green.
8. Full suite green: `cd bridge && uv run ruff check . && uv run pytest` (and `agents/` unchanged).
   The retargeted `test_seam_interfaces.py` extraction test passes.

## Gotchas recap
- **Do NOT build an ADK `Workflow`** — deterministic state machine (see the design-decision section).
- **Do NOT re-derive thresholds/routing** — call `classify_document`/`run_disposition_gate` (M1.6) and
  route on the returned `Gate`. Single-source the gate.
- **`test_seam_interfaces.py::test_extraction_skeleton_defers` WILL break** — retarget it (files-to-modify #4).
- **A1 is the correctness heart:** `resubmit` non-resumable (awaits a fresh doc); escalation is
  PENDING, never rejected; resumable = `{hitl, escalated}` only.
- **`attempts` threads forward across resubmissions** even though resubmit is non-resumable — the
  caller passes `attempts=prev.attempts` into the next `run_fulfillment`; the counter persisting is
  what makes "≤ 3 then escalate" work.
- **`extraction_error` ≠ `resubmit` ≠ `unsupported`:** engine fault vs low-confidence-readable vs
  wrong-doctype — three distinct leaves.
- **Reimplement the eval loader in `bridge/`** (walk-up, honor `ADDRESS_EVALS_PATH`); never import the
  mock's `fixtures.py`.
- **Keep new modules out of `bridge/__init__.py`** and the graph out of `bridge/adapters` imports.
- **`ExtractionError` lives in `seams/extraction.py`** (interface layer), imported by both adapter and graph.
