# M1.0 — Shared `contract` package move (prereq)

**Milestone:** 1 (Bridge Core, local) · **Task line:** `PLAN.md` M1.0 · **Blocks:** all of M1.
**Depends on:** S0.2 (bridge scaffold + `no-agents-import` guard), S0.8 (ADR-0011 ratified).
**Governing ADR:** `docs/decisions/adr-0011-contract-type-sharing.md` (**Accepted**) — this task executes the "follow-up mechanics" section (§Sign-off gate, steps 1–6). Read it first; this plan makes those steps concrete and adds the CI/tooling gotchas the ADR omits.

## Goal (scope of THIS task only)

Physically relocate the `contract` package from `agents/src/contract/` to a **new, separate, root-level uv project `contract/`**, and rewire `agents/` and `bridge/` to depend on it as a uv **path dependency** (editable). Outcome: `bridge/` can produce/consume the exact shipped contract shapes (`CollectRequest`, `ExchangeTurn`, `CollectionStatus`, `LedgerEntry`, `Requirement`/`RequirementsList`, `Extraction`/`ExtractedFields`, `Disposition`, `RequirementStatus`, incl. the ADR-0013 `reason_code`/`message` fields) **without importing `agents/`**, and the `bridge/tests/test_no_agents_import.py` guard stays green.

The import name stays `contract` in both projects — **zero call-site churn**. This is a mechanical move + dependency rewire + re-lock + CI/tooling touch-ups. **No model/logic changes to the contract types themselves.**

### Explicitly NOT in this task
- No new contract fields or behavior. Move the code **byte-for-byte** (`git mv`); do not "improve" it.
- No seam interfaces, no `bridge/` domain logic (that's M1.1+).
- Do not move `agents/tests/test_contract.py` (it keeps importing `contract` and stays green in the agents job — see Decision D3). Moving it would require a new CI job; out of scope.

## Context an executor needs (do not re-derive)

- **Three peer uv projects after this task:** `agents/`, `bridge/`, and the new `contract/` — all at repo root, each with its own `pyproject.toml` / `uv.lock` / `.venv`. **Not** a uv workspace (there is no root `pyproject.toml`; confirmed none exists). Run all `uv`/`pytest`/`ruff` commands from **inside each project dir**.
- **uv is v0.9.1**, Python 3.12 pinned per project via `.python-version` (single line `3.12`).
- **Current call sites** that `import contract` (all resolve unchanged after the move because both projects will depend on the path package):
  - `agents/src/bridge_client/remote_consumer.py`, `wire.py` (docstrings + imports)
  - `agents/src/agents/address/satisfaction.py`, `graph.py`
  - `agents/src/agents/mock_bridge/fixtures.py`, `executor.py`
  - tests: `agents/tests/test_contract.py`, `test_interceptor.py`, `test_mock_bridge.py`, `test_native_consumer.py`, `test_scaffold.py`, `test_satisfaction.py`
  - **`bridge/` currently has NO contract imports** — it gains the dependency here for M1.1+ to use.
- **The invariant** (`CLAUDE.md`): `bridge/` never imports `agents/`. A shared *third* package is explicitly allowed. After the move, `bridge/` depends on `contract` (allowed), never `agents`. The guard test scans `sys.modules` for `agents.*` after `import bridge` — importing `contract` does not pull in `agents`, so it stays green. **Verify this explicitly (acceptance A4).**
- **Contract package has only one runtime dep: `pydantic>=2`.** No ADK, no a2a-sdk — keep it lightweight (ADR-0011 rationale: minimizes cross-project lock churn).
- **`agents/pyproject.toml` currently lists `src/contract` in `[tool.hatch.build.targets.wheel].packages`** (line: `packages = ["src/agents", "src/bridge_client", "src/contract"]`). This MUST be dropped once the dir is gone, or the agents editable install breaks.

## Design decisions (made here so the executor doesn't re-litigate)

- **D1 — Location = root `contract/`** (not `packages/contract/`). Matches the ADR's `path = "../contract"` example and the flat sibling layout of `agents/`/`bridge/`.
- **D2 — Distribution name `a2a-document-bridge-contract`, import name `contract`.** src layout, hatchling wheel target `packages = ["src/contract"]`.
- **D3 — Leave `agents/tests/test_contract.py` in `agents/`.** It imports `contract` (resolves via the path dep) and stays green in the agents CI job. Adding a dedicated `contract` CI job/test suite is out of scope. (Optional future cleanup, not now.)
- **D4 — Give `contract/` its own committed `uv.lock`** for reproducibility parity with the other two projects (pydantic-only, cheap). Not strictly required for the path dep to work, but keeps `uv sync --locked` viable everywhere and matches repo convention.
- **D5 — Extend CI path filters so a `contract/**` change triggers BOTH the `agents` and `core` jobs** (see Step 6 — the ADR omits this; without it a contract change ships untested).

## Ordered steps

### 1. Create the `contract/` project skeleton
- `contract/.python-version` → single line `3.12` (mirror `agents/.python-version`).
- `contract/pyproject.toml`:
  ```toml
  [project]
  name = "a2a-document-bridge-contract"
  version = "0.0.0"
  requires-python = ">=3.12"
  dependencies = [
      "pydantic>=2",
  ]

  [dependency-groups]
  dev = [
      "pytest>=8",
      "ruff>=0.6",
  ]

  [build-system]
  requires = ["hatchling"]
  build-backend = "hatchling.build"

  [tool.hatch.build.targets.wheel]
  packages = ["src/contract"]

  [tool.ruff]
  line-length = 100
  target-version = "py312"
  src = ["src", "tests"]

  [tool.ruff.lint]
  select = ["E", "F", "I"]

  [tool.pytest.ini_options]
  testpaths = ["tests"]
  addopts = "-ra"
  ```
  (dev group + ruff/pytest config mirror the other two projects so `make lint`/`make fmt` stay uniform even though no contract tests are added now.)

### 2. Move the code (byte-for-byte)
- `git mv agents/src/contract contract/src/contract` (moves `__init__.py` + `models.py` with history). Do **not** edit their contents — the re-exports and models are unchanged.
- Result: `contract/src/contract/__init__.py`, `contract/src/contract/models.py`.

### 3. Rewire `agents/pyproject.toml`
- Add `"a2a-document-bridge-contract"` to `[project].dependencies`.
- Add a sources table:
  ```toml
  [tool.uv.sources]
  a2a-document-bridge-contract = { path = "../contract", editable = true }
  ```
- In `[tool.hatch.build.targets.wheel]`, change
  `packages = ["src/agents", "src/bridge_client", "src/contract"]`
  → `packages = ["src/agents", "src/bridge_client"]` (drop the now-gone `src/contract`).

### 4. Rewire `bridge/pyproject.toml`
- Add `"a2a-document-bridge-contract"` to `[project].dependencies`.
- Add the same sources table:
  ```toml
  [tool.uv.sources]
  a2a-document-bridge-contract = { path = "../contract", editable = true }
  ```
- Leave `[tool.hatch.build.targets.wheel].packages = ["src/bridge"]` unchanged.

### 5. Re-lock all three projects (order matters)
- From `contract/`: `uv lock` (generates `contract/uv.lock`).
- From `agents/`: `uv sync` (regenerates `agents/uv.lock` with the path dep; installs contract editable into agents' `.venv`).
- From `bridge/`: `uv sync` (regenerates `bridge/uv.lock`; installs contract editable into bridge's `.venv`).
- **Commit all three lockfiles** (`uv.lock` is tracked, not gitignored — SDK pins are load-bearing per ADR-0001). If `uv.lock`s aren't regenerated+committed, CI's `uv sync --locked` will fail.

### 6. CI path filters (`.github/workflows/ci.yml`) — the ADR omits this
- In the `changes` job's `paths-filter` `filters:`, add `- 'contract/**'` under **both** the `agents:` and `core:` filter lists, so a contract-only change runs both consumer jobs. Example:
  ```yaml
  agents:
    - 'agents/**'
    - 'contract/**'
    - '.github/workflows/ci.yml'
  core:
    - 'bridge/**'
    - 'contract/**'
    - '.github/workflows/ci.yml'
  ```
- No new dedicated `contract` job (D3): the package is exercised through both consumer jobs.

### 7. Tooling touch-ups
- **`.pre-commit-config.yaml`:** widen the two ruff hook `files` regexes from `^(agents|bridge)/.*\.py$` to `^(agents|bridge|contract)/.*\.py$` (both the `ruff` and `ruff-format` hooks) so the moved code stays linted/formatted.
- **`Makefile`:** the `setup` target already `uv sync`s agents + bridge (which pull contract editable), so no change is strictly required. Optional: add `cd contract && uv sync` to `setup` for parity. `test`/`lint`/`fmt` need no change (D3: no contract tests; ruff runs via pre-commit + the agents/bridge project ruff).

### 8. Doc pointer updates (light — don't rewrite history)
- Update the **living** doc that describes current layout if it names the old path. Check `agents/README.md` for a layout/tree section mentioning `src/contract` and repoint to `../contract`.
- Do **NOT** rewrite historical plan files under `.claude/plans/` or completed-milestone docs (`docs/milestone-0-contract-tracer.md`, ADR bodies) — those are point-in-time records. ADR-0011 already documents the move.
- Optionally add a one-line note to `docs/lessons-learned.md` if there's a layout/invariant section, stating the contract types now live in the root `contract/` project (import name unchanged).

- **A6 —** `agents/pyproject.toml` wheel `packages` no longer lists `src/contract`; both `agents/` and `bridge/` `pyproject.toml` carry the `[tool.uv.sources]` path dependency.
- **A7 —** CI `changes` filters route `contract/**` edits to both `agents` and `core` jobs.
- **A8 —** `ruff check` clean in all three projects; pre-commit ruff hooks now cover `contract/*.py`.

## Gotchas (ordered by how likely they are to bite)
1. **Forgetting to re-lock → CI red.** CI runs `uv sync --locked`, which fails if the lockfile doesn't match `pyproject.toml`. You MUST run `uv lock`/`uv sync` in every project you touched and commit the new `uv.lock`s.
2. **Dropping `src/contract` from agents' wheel packages.** If left in, hatchling errors (path missing) or the editable install is inconsistent. Remove it in the same edit that moves the dir.
3. **CI path filters (Step 6).** Easy to miss because the ADR mechanics don't mention it. Without it, a `contract/`-only PR triggers neither consumer job and ships untested.
4. **`uv lock` in `contract/` before `uv sync` in the consumers** — do the consumers after the contract project so the path resolves cleanly (editable path deps don't strictly need the dep's lock, but doing contract first avoids confusion).
5. **Do not edit the moved files' contents.** The models are the wire contract under validation; a stray reformat that changes field order/defaults is a contract change. `git mv` + leave alone.
6. **`use_legacy`/experimental surfaces are untouched** — this task doesn't go near the consumer runtime; don't get pulled into adjacent refactors.
