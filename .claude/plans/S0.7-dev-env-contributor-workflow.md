# S0.7 — Dev-env + contributor workflow

**Sprint:** 0 (scaffolding) · **Task line:** `PLAN.md` S0.7
**Goal:** Make setup **one command** and lint **automatic**. Stand up a root task runner
(`Makefile`), a `pre-commit` config that mirrors CI, a consolidated `.env.example` convention, and a
`CONTRIBUTING.md` so a new contributor goes clone → one command → green in minutes. **No application
code, no seams, no domain behavior** — this is cross-cutting developer tooling only.

---

## Context an executor needs (do not re-derive)

The repo is a **polyglot monorepo** with four already-scaffolded sub-projects, each with its own
toolchain and lockfile. S0.7 does **not** create or modify any of them — it wraps them:

| Project | Toolchain | Lint | Test | Format |
|---|---|---|---|---|
| `agents/` | uv (own `.python-version`=3.12, `uv.lock`) | `uv run ruff check .` | `uv run pytest` | `uv run ruff format .` |
| `bridge/` | uv (own `.python-version`=3.12, `uv.lock`) | `uv run ruff check .` | `uv run pytest` | `uv run ruff format .` |
| `frontend/` | pnpm 10.33.0 (`pnpm-lock.yaml`) | `pnpm lint` (eslint) | `pnpm test` (vitest) | `pnpm format` / `pnpm format:check` (prettier) |
| `infra/terraform/` | Terraform 1.15+ | `terraform fmt -check -recursive` + `validate` | — | `terraform fmt -recursive` |
| `skills/` | (config only) | `uvx --from skills-ref==0.1.1 agentskills validate <dir>` | — | — |

- **uv must run from inside each project dir** — the uv project root is `agents/`/`bridge/`, not repo
  root (each carries its own `.python-version` + `uv.lock`). Makefile recipes therefore use
  `cd agents && uv ...` on a single line (each recipe line is its own shell).
- **Ruff config is identical** in both `agents/pyproject.toml` and `bridge/pyproject.toml`:
  `line-length = 100`, `target-version = "py312"`, `[tool.ruff.lint] select = ["E","F","I"]`,
  `ruff>=0.6` pinned as a dev dep. Ruff auto-discovers the nearest `pyproject.toml` per file, so a
  root-level ruff invocation (pre-commit) applies each project's config correctly.
- **CI already exists** (`.github/workflows/ci.yml`, S0.1/S0.6): jobs agents/core/skills/frontend +
  a `ci-success` aggregation job. **The single required status check is `ci-success`** — the Makefile
  `lint`/`test` targets and pre-commit hooks must run the *same commands CI runs* so "green locally →
  green in CI" holds. Do **not** modify `ci.yml` in this task (it is the merge gate; S0.1/S0.6 own it).
- **`.gitignore` already handles env/secrets correctly:** `.env` and `.env.*` ignored, `!.env.example`
  tracked. Verified: `agents/src/agents/address/.env.example` is tracked; no stray `.env` is tracked.
  Item 3 is mostly a **consolidation + confirmation** task, not new ignore rules.
- **The only existing `.env.example`** is `agents/src/agents/address/.env.example` (Vertex vars +
  `ADDRESS_AGENT_MODEL`, `BRIDGE_CARD_URL`, `BRIDGE_BASE_URL` as commented overrides). It **must stay
  where it is** — `adk web` auto-loads `.env` from the agent package folder, so that file's location
  is load-bearing. Do not move it. The mock server also reads `MOCK_BRIDGE_HOST/PORT/HOLD_SECONDS/PARK`
  (documented in `agents/README.md`).
- **`skills/README.md` already documents** the local `agentskills validate` command and explicitly says
  "will be folded into the root dev-env doc / pre-commit in S0.7" — so S0.7 must (a) add the skills
  validate to `make lint` + pre-commit and (b) reference it from `CONTRIBUTING.md`. Keep the pinned form
  `uvx --from skills-ref==0.1.1 agentskills validate` (S0.6 gotcha: the PyPI package `skills-ref`
  exposes the `agentskills` executable, **not** `skills-ref`).
- **Tooling present on the dev box:** uv 0.9.1, pnpm 10.33.0, Terraform 1.15.8. `pre-commit` is **not**
  installed — `make setup` must install/enable it (via uvx or as a dev tool), and `CONTRIBUTING.md`
  must tell contributors to run `pre-commit install`.

## Design decisions (baked in — don't re-litigate)

1. **Task runner = root `Makefile`** (not justfile). Rationale: zero install (`make` is ubiquitous on
   Linux/macOS dev + CI images), matches the "one command" ask, and the task line lists Makefile first.
   Provide `.PHONY` targets and a `help` default target.
2. **Targets:** `setup`, `test`, `lint`, `fmt` (required by task) plus `help` (default). Each aggregates
   across all sub-projects. Also add convenience per-project targets only if trivial (optional; not
   required). `setup` = install everything + enable pre-commit; `lint`/`test`/`fmt` fan out.
3. **`make lint` / `make test` mirror CI exactly** (same commands as `ci.yml`) so local green ⇒ CI green.
   Use `uv sync --locked` semantics? No — for *dev* `setup` use plain `uv sync` (installs + allows lock
   refresh is NOT wanted; use `uv sync` which respects the lock). Keep `--locked` for CI only; `make
   setup` uses `uv sync` (fast, honors committed lock). Note this divergence explicitly in a comment.
4. **`pre-commit` hooks use the projects' own toolchains** where a clean path exists, to keep a single
   source of truth for tool versions:
   - **Python:** use the official **`astral-sh/ruff-pre-commit`** repo hooks (`ruff-check` with
     `--fix` + `ruff-format`), pinned to a `v0.6.x`+ tag, `files: ^(agents|bridge)/.*\.py$`. Ruff
     auto-discovers each project's `pyproject.toml` — no `cd` needed, sidesteps the path problem below.
   - **Frontend (prettier), Terraform (fmt), Skills (validate):** **local `language: system` hooks**
     with `pass_filenames: false`, scoped by `files:` regex, each running the exact project command
     (`pnpm -C frontend run format`, `terraform -chdir=infra/terraform fmt -recursive`, the skills
     validate loop). `pass_filenames: false` deliberately avoids pre-commit's relative-path breakage
     when a tool needs a different working dir (`-C`/`-chdir`).
   - Baseline hygiene hooks from `pre-commit/pre-commit-hooks`: `trailing-whitespace`,
     `end-of-file-fixer`, `check-yaml`, `check-merge-conflict`, `check-added-large-files`.
   - **Do NOT** put eslint in pre-commit (slow, and CI's `pnpm lint` covers it) — pre-commit does
     *formatting/fast* checks; the full lint gate is CI + `make lint`.
5. **`.env` consolidation = one canonical root `.env.example` + confirmation**, not a move. Add a
   root-level `.env.example` that enumerates every env var across the repo with pointers to where each
   `.env` actually lives (agents package folder for `adk web`), keep the existing agents one in place,
   and confirm gitignore. This gives contributors one place to read; the load-bearing per-folder file
   stays.
6. **`CONTRIBUTING.md` is the contributor doc**; add a short "Development" pointer to it from root
   `README.md` (README already has a "Stack"/"Status" section — add a one-line link, don't rewrite it).

## Ordered steps

### 1. Create root `Makefile`

`.PHONY: help setup test lint fmt`. Default goal = `help`. Concrete recipes (each `cd` line is one
shell):

```make
.DEFAULT_GOAL := help
.PHONY: help setup test lint fmt

help:  ## Show this help
	@grep -E '^[a-zA-Z_-]+:.*?## .*$$' $(MAKEFILE_LIST) | \
	  awk 'BEGIN{FS=":.*?## "}{printf "  \033[36m%-10s\033[0m %s\n", $$1, $$2}'

setup:  ## One-command dev setup: install all deps + enable pre-commit
	cd agents && uv sync
	cd bridge && uv sync
	cd frontend && pnpm install
	uvx pre-commit install
	@echo "Setup complete. Run 'make test' and 'make lint'."

test:  ## Run all test suites (agents, bridge, frontend)
	cd agents && uv run pytest
	cd bridge && uv run pytest
	cd frontend && pnpm test

lint:  ## Lint/format-check everything (mirrors CI)
	cd agents && uv run ruff check .
	cd bridge && uv run ruff check .
	cd frontend && pnpm lint
	terraform -chdir=infra/terraform fmt -check -recursive
	for d in skills/*/; do [ -f "$${d}SKILL.md" ] && uvx --from skills-ref==0.1.1 agentskills validate "$$d" || true; done

fmt:  ## Auto-format everything
	cd agents && uv run ruff format . && uv run ruff check --fix .
	cd bridge && uv run ruff format . && uv run ruff check --fix .
	cd frontend && pnpm format
	terraform -chdir=infra/terraform fmt -recursive
```

Gotchas to honor in the recipe:
- `$$` escapes `$` for Make; `$${d}` and the awk/grep `$$1` above are intentional.
- The skills loop must **not** mask a real validation failure — the demo above uses `|| true` for
  robustness against the `[ -f ]` guard; instead prefer the S0.6-style accumulate-status loop so a bad
  skill fails `make lint`. Use:
  `for d in skills/*/; do [ -f "$${d}SKILL.md" ] || continue; uvx --from skills-ref==0.1.1 agentskills validate "$$d" || exit 1; done`
- Consider a `terraform validate` line in `lint` too (CI runs it): it needs `terraform -chdir=... init
  -backend=false` first. Keep `lint` fast — `fmt -check` is the cheap gate; add validate as an optional
  `make tf-validate` target or a commented line, matching CI's `fmt -check` + `validate` (document the
  choice).

### 2. Create `.pre-commit-config.yaml` (repo root)

```yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0            # pin to a real released tag
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-merge-conflict
      - id: check-added-large-files

  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9            # pin >=0.6 to match the projects' ruff dep
    hooks:
      - id: ruff-check
        args: [--fix]
        files: ^(agents|bridge)/.*\.py$
      - id: ruff-format
        files: ^(agents|bridge)/.*\.py$

  - repo: local
    hooks:
      - id: prettier-frontend
        name: prettier (frontend)
        language: system
        pass_filenames: false
        files: ^frontend/.*\.(ts|tsx|js|jsx|json|css|md)$
        entry: bash -c 'pnpm -C frontend run format:check'
      - id: terraform-fmt
        name: terraform fmt
        language: system
        pass_filenames: false
        files: ^infra/.*\.tf$
        entry: bash -c 'terraform -chdir=infra/terraform fmt -check -recursive'
      - id: skills-validate
        name: agentskills validate
        language: system
        pass_filenames: false
        files: ^skills/.*
        entry: bash -c 'for d in skills/*/; do [ -f "$${d}SKILL.md" ] || continue; uvx --from skills-ref==0.1.1 agentskills validate "$$d" || exit 1; done'
```

Notes / decisions:
- Verify the exact latest tags for `pre-commit-hooks` and `ruff-pre-commit` at implement time (pin to a
  real tag, not a floating ref). `ruff-check` is the current hook id (older configs used `ruff`);
  confirm against the pinned rev.
- Local hooks use `format:check` / `fmt -check` (non-mutating) so pre-commit **reports** rather than
  silently rewriting frontend/terraform files; ruff hooks *do* auto-fix Python (idiomatic). This
  asymmetry is deliberate — document it in `CONTRIBUTING.md` (run `make fmt` to fix frontend/tf).
- Local `language: system` hooks require `pnpm`, `terraform`, `uvx` on PATH — provided by `make setup`.
  State this dependency in `CONTRIBUTING.md`.

### 6. Verify locally

Run and confirm green (this is the acceptance evidence):
```bash
make setup          # installs agents+bridge (uv), frontend (pnpm), enables pre-commit
make fmt            # normalize formatting first (see gotcha below)
make lint           # ruff + eslint + terraform fmt-check + skills validate all pass
make test           # agents pytest (~49) + bridge pytest + frontend vitest all pass
uvx pre-commit run --all-files   # every hook passes
```

**Critical gotcha — pre-existing files must pass the hooks.** `pre-commit run --all-files` and
`make lint` will fail if any already-committed file doesn't satisfy ruff-format / prettier / terraform
fmt. Run `make fmt` first; if it produces diffs in tracked files, **commit those formatting changes as
part of S0.7** (they are expected, one-time normalization). Do not weaken a hook to make a dirty file
pass — fix the file.

## Gotchas recap

- **uv runs per-project** — `cd agents && uv ...`, never repo-root uv. Each recipe line is its own shell.
- **Pre-existing files must pass hooks** — run `make fmt`, commit the resulting normalization diffs;
  never weaken a hook to pass a dirty file.
- **`skills-ref` PyPI package → `agentskills` executable** (not `skills-ref`); pinned
  `uvx --from skills-ref==0.1.1 agentskills validate` (S0.6).
- **Don't move the agents `.env.example`** — `adk web` auto-loads `.env` from the agent package folder;
  the root `.env.example` is only a reference index.
- **Local `language: system` pre-commit hooks need pnpm/terraform/uvx on PATH** (provided by
  `make setup`); they use `pass_filenames: false` to avoid working-dir/relative-path breakage.
- **Frontend/terraform hooks are check-only**, ruff auto-fixes — document "`make fmt` to fix" so a
  failing prettier/tf hook isn't surprising.
- **Mirror CI commands exactly** so `make lint && make test` green ⇒ `ci-success` green. Don't invent
  new invocations. Don't edit `ci.yml` here.
- **`make setup` uses `uv sync`** (honors committed lock, fast); CI uses `uv sync --locked` (drift
  guard) — the divergence is intentional; note it in the Makefile.
