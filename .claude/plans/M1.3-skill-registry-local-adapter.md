## Goal (scope of THIS task only)

Turn the M1.1 `LocalSkillRegistry` **skeleton** into a working, directory-backed local adapter, and define the concrete **Skill / policy types** the M1.1 Protocol deferred to M1.3. Three deliverables:

1. **Concrete skill types** in a new pure module `bridge/src/bridge/skills.py`: `SkillKind`, `SkillPolicy` (disposition thresholds + retry + SLA), and `Skill` (the loaded Agent-Skills folder — `name`/`description`/`kind`/`metadata`/`body` + resolved policy for process skills). These are the "concrete Skill/policy types M1.3 defines" the seam docstring points at.
2. **`LocalSkillRegistry`** real behavior: scan a directory of Agent Skills folders, parse each `SKILL.md` (YAML frontmatter + Markdown body), and for a process skill load its `bridge-policy` asset (`assets/policy.yaml`) into `SkillPolicy`. Load `skills/address-proof/` (+ the `gov-id`/`utility-bill` doctype skills that share the tree). Expose `list_skills()`, `get_skill(name)`, and the **Agent-Card source** (`agent_skills()` → `list[AgentSkill]`, plus a `build_agent_card(...)` convenience).
3. **Factory wiring + tests**: `build_local_adapter(Seam.SKILL_REGISTRY)` resolves a default skills root; the seam suite proves the registry loads the real `skills/` tree and surfaces the ADR-0002 thresholds + C1 SLA values + the dynamic card.

### Explicitly NOT in this task
- **No disposition / classification logic** — M1.6. M1.3 only *exposes* the thresholds (`0.55`/`0.85`) and the candidate-doctype label space (`gov-id utility-bill`); it does not run a gate or classify anything.
- **No scheduler/SLA engine** — M1.12. M1.3 only *exposes* `SkillPolicy.sla` (cadence/deadline/max-nudges); no timers.
- **No A2A server** — M1.8 stands up the JSON-RPC edge and wires the card into `DefaultRequestHandler`. M1.3 only *generates* the `AgentCard`/`AgentSkill` objects the edge will serve.
- **No deep doctype-asset parsing** — the `schema.json` / `validation.yaml` contents are consumed by M1.6 (validation/signals) and M1.7 (extraction schema). M1.3 loads the folders and resolves asset **paths**, but does not parse `schema.json`/`validation.yaml` into typed models. Expose the raw asset path (+ metadata) and leave a `# M1.6/M1.7 parse schema/validation` note.
- **No GCP adapter** — Sprint 2 (managed Skill Registry). The `gcp` fixture branch keeps skipping. "Directory-backed" is still the **local** adapter.
- **No live skill-add / card-regeneration flow** — Phase 3 (`wiki/bridge-skills.md`). M1.3 loads a static directory at construction; hot-reload is out of scope.
- **No env-var seam *selection* beyond the skills-root path** — C3 `BRIDGE_SEAM_*` general wiring stays deferred (M1.2 comment already in the factory). This task adds only the skills-root resolver (`BRIDGE_SKILLS_DIR`), analogous to the address agent's `BRIDGE_CARD_URL` swap point.

## Design decisions (made here — do not re-litigate)

- **D1 — Concrete types in a new pure module `bridge/src/bridge/skills.py`** (parallel to `aggregate.py`). Imports only `contract`(if needed)/`a2a.types`/`pydantic`/stdlib — never `agents`, never `bridge.seams`/`bridge.adapters` (one-way dependency: adapters → skills, never the reverse). Types (pydantic `BaseModel`s, frozen where natural):
  - `class SkillKind(str, Enum): PROCESS = "process"; DOCTYPE = "doctype"`.
  - `class DispositionThresholds(BaseModel): resubmit_below: float = 0.55; auto_approve_at: float = 0.85` (ADR-0002 defaults — used when a process skill omits them).
  - `class SlaPolicy(BaseModel): deadline: int; cadence: int; max_nudges: int` (ticks; C1).
  - `class SkillPolicy(BaseModel): thresholds: DispositionThresholds; max_resubmissions: int = 3; sla: SlaPolicy | None = None`. Built from `assets/policy.yaml` (`thresholds`, `retry.max_resubmissions`, `sla`). Doctype skills have `policy = None`.
  - `class Skill(BaseModel): name: str; description: str; kind: SkillKind; metadata: dict[str, str]; body: str = ""; path: Path; policy: SkillPolicy | None = None; candidate_doctypes: tuple[str, ...] = ()`. Add a convenience `asset_path(rel: str) -> Path` (resolves `metadata`-referenced assets like `bridge-schema`/`bridge-policy` under `self.path`). `candidate_doctypes` is the split of `metadata["bridge-candidate-doctypes"]` (process skills only). Leave a `# M1.6/M1.7 parse schema.json / validation.yaml from asset_path(...)` note.
- **D2 — `LocalSkillRegistry(root: Path | str)` loads eagerly at construction and caches.** Scan immediate subdirectories of `root` that contain a `SKILL.md`; parse each into a `Skill`; index by `name`. The async accessor methods (`list_skills`/`get_skill`) return cached data (they stay `async` to match the Protocol; no I/O in the awaited path). A missing/empty `root` yields an **empty registry** (do not raise) — so a bare conformance `isinstance` test and a not-yet-populated deploy don't crash. Log/ignore a subdir whose `SKILL.md` fails to parse? Prefer **raise a clear error at construction** for a malformed *present* skill (fail loud on bad data), but treat an *absent* `SKILL.md` as "not a skill folder, skip". Document this split.
- **D3 — Default skills-root resolution mirrors the address agent's card-URL swap point.** The factory must keep the existing no-arg call site (`LocalSkillRegistry()` in `build_local_adapter`) working, so give `LocalSkillRegistry.__init__` a **default root resolver**: `root` defaults to `resolve_default_skills_dir()`, a module function in `bridge/src/bridge/skills.py` that returns `Path(os.environ["BRIDGE_SKILLS_DIR"])` if set, else walks up from `__file__` to the first ancestor containing a `skills/` directory and returns it (repo root `/home/boris/working/skills`), else falls back to `Path.cwd()/"skills"`. This is the single documented place `bridge/` references the shared repo `skills/` tree; add a one-line comment tying it to C3 (env selector) like the M1.2 factory comment. Keep `build_local_adapter(Seam.SKILL_REGISTRY)` a no-arg `LocalSkillRegistry()` — the default resolver does the work.
- **D4 — Agent-Card generation belongs to the registry (it *is* the discovery surface — `wiki/bridge-skills.md`).** Add to `LocalSkillRegistry`:
  - `def agent_skills(self) -> list[a2a.types.AgentSkill]`: map each **process** skill → `AgentSkill(id=skill.name, name=<Title>, description=skill.description, tags=[...], input_modes=["application/json"], output_modes=["application/json"])`. Process skills are the servicer-facing capabilities the card advertises (the mock advertised only `address-proof`); doctype skills are internal to extraction and are **not** carded. State this rule in the docstring.
  - `def build_agent_card(self, *, base_url: str, version: str = "0.0.0", capabilities: AgentCapabilities | None = None) -> AgentCard`: assemble a card whose top-level `name`/`description` derive from the registry (e.g. name `"A2A Document Bridge"`, description summarizing the advertised process skills — or, if exactly one process skill, reuse its description) and `skills=self.agent_skills()`. Interface URL/capabilities/version are edge concerns → args with defaults (mirror the mock's `AgentInterface`/`AgentCapabilities(streaming=True, push_notifications=False)`). M1.8 will call this. Keep it a thin, sync helper.
- **D5 — Extend the `SkillRegistrySeam` Protocol to the M1.3 contract.** Tighten `list_skills() -> list["Skill"]`, `get_skill(name) -> "Skill | None"` (string / `TYPE_CHECKING` annotations to avoid a cycle), and **add** `def agent_skills(self) -> list[AgentSkill]` and `def build_agent_card(self, *, base_url: str, ...) -> AgentCard` to the Protocol so the seam contract states "the registry is the card source" (the Sprint-2 GCP adapter must satisfy the same). `agent_skills`/`build_agent_card` are **sync** (pure over cached data); `list_skills`/`get_skill` stay **async** (Protocol parity). Update the Protocol docstring to name `Skill`/`SkillPolicy` as the now-concrete types.
- **D6 — Do not over-model doctype skills.** A `Skill` with `kind=DOCTYPE` carries `metadata` (incl. `bridge-extraction-engine`, `bridge-schema`) + `asset_path()`; M1.6/M1.7 parse the referenced assets. No `Schema`/`Validation` models here.
