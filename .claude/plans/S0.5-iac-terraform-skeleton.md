# S0.5 — IaC (Terraform) skeleton — layout + fmt/validate only

**Sprint:** 0 (scaffolding) · **Task line:** `PLAN.md` S0.5
**Goal:** Lay the `infra/` Terraform **structure** (directory convention + provider pins +
commented remote-state backend) and wire a **credential-free** CI gate that runs
`terraform fmt -check` + `terraform validate` — **no `plan`, no `apply`, no GCP credentials, no
resources.** Base infra (the 8 modules, real resources) is **Sprint 2**; Sprint 0 only lays the
skeleton so Sprint 2 isn't retrofitted into an empty tree.

Depends on: **S0.1** (CI workflow exists — this task adds an `infra` job to it and extends the
`changes` filter + `ci-success` aggregation). Unblocks: **S0.7** (pre-commit `terraform fmt`),
Sprint 2 base infra.

## Design decisions (baked in — don't re-litigate)

1. **Root module lives at `infra/terraform/`**; child modules under `infra/terraform/modules/`;
   per-environment backend + var files under `infra/terraform/envs/`. This is the "module/`envs`
   directory convention" the task asks for. Only the **root** is fmt/validated in Sprint 0 (there are
   no modules yet); `fmt -check -recursive` still covers everything once modules arrive.
2. **`versions.tf` pins the provider and stubs the backend.** `required_version = ">= 1.5"`;
   `required_providers` → `google` from `hashicorp/google` pinned `~> 6.0` (current major; Sprint 2 may
   tighten to an exact minor). The `backend "gcs"` block is **commented out** with a note that it's
   enabled once the state bucket exists (Sprint 2) and that per-env backend config lives in `envs/`.
   Commented backend = `init -backend=false` and `validate` work today with zero cloud state.
3. **A `provider "google"` block IS declared** (project + region from vars). `validate` needs the
   provider installed (via `init`) but never calls GCP, so an un-credentialed provider block validates
   fine (prototyped). This establishes the provider-config convention Sprint 2 extends. Keep the two
   core vars (`project_id` with **no default**, `region` defaulting to `us-central1`) so the root
   parses meaningfully.
4. **CI runs `fmt -check -recursive` → `init -backend=false` → `validate`** — in that order,
   `working-directory: infra/terraform`. `init -backend=false` is **required** before `validate`
   (validate needs the provider schema); `-backend=false` keeps it stateless/credential-free. **No
   `plan`, no `apply`, no secrets** (task mandate + roadmap risk).
5. **Pin `hashicorp/setup-terraform`** to a commit SHA (supply-chain hygiene, same as every other
   action in the file). Use **v3.1.2 = `b9cd54a3c349d3f38e8881555d616ced269862dd`** (looked up during
   planning; v4.0.1 = `dfe3c3f87815947d99a8997f908cb6525fc44e9e` is the alternative). Set
   `terraform_wrapper: false` so the CLI isn't wrapped (clean exit codes for `fmt -check`), and pin
   `terraform_version` to `~> 1.9` (or the runner default) — do not float.
6. **No `terraform test` / `*.tftest.hcl` in Sprint 0.** The task says "fmt/validate only," and a
   skeleton with zero resources has nothing meaningful to `mock_provider`-test. Record in the infra
   README that the `*.tftest.hcl` credential-free suite (§C4, "the *only* proof the config was
   coherent") is the **Sprint-2** validation mechanism. Do not build it now.
7. **Do NOT create the 8 child modules.** Establish `modules/` as a convention dir with a `README.md`
   listing the planned modules (pointing at `docs/features/gcp-infra.md` + §C4) and a `.gitkeep` so the
   empty dir is committed. Same for `envs/`.

### 2. `infra/terraform/versions.tf`
```hcl
terraform {
  required_version = ">= 1.5"

  required_providers {
    google = {
      source  = "hashicorp/google"
      version = "~> 6.0"
    }
  }

  # Remote state — enable once the tfstate bucket exists (Sprint 2).
  # Per-environment backend config lives in envs/<env>/backend.hcl
  # (terraform init -backend-config=envs/<env>/backend.hcl).
  # backend "gcs" {
  #   bucket = "REPLACE_ME-tfstate"
  #   prefix = "bridge"
  # }
}

provider "google" {
  project = var.project_id
  region  = var.region
}
```

### 3. `infra/terraform/variables.tf`

variable "project_id" {

### 9. Wire CI (`.github/workflows/ci.yml`)
Three edits, matching the existing pattern (pinned SHAs, `hashFiles` guard, `ci-success` aggregation):

**(a) Add `infra` output to the `changes` job:**
```yaml
    outputs:
      agents:   ${{ steps.filter.outputs.agents }}
      core:     ${{ steps.filter.outputs.core }}
      skills:   ${{ steps.filter.outputs.skills }}
      frontend: ${{ steps.filter.outputs.frontend }}
      infra:    ${{ steps.filter.outputs.infra }}
```
and a filter:
```yaml
            infra:
              - 'infra/**'
              - '.github/workflows/ci.yml'
```

**(b) Add the `infra` job** (guard on the filter AND `versions.tf` existence so it stays skipped if
the tree is ever absent; it will fire immediately after this task lands):
```yaml
  infra:
    needs: changes
    if: needs.changes.outputs.infra == 'true' && hashFiles('infra/terraform/versions.tf') != ''
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: infra/terraform
    steps:
      - uses: actions/checkout@eef61447b9ff4aafe5dcd4e0bbf5d482be7e7871   # v4.2.1
      - uses: hashicorp/setup-terraform@b9cd54a3c349d3f38e8881555d616ced269862dd # v3.1.2
        with:
          terraform_version: "~> 1.9"
          terraform_wrapper: false
      - run: terraform fmt -check -recursive
      - run: terraform init -backend=false
      - run: terraform validate
```

**(c) Add `infra` to the `ci-success` `needs` list:**
```yaml
    needs: [changes, agents, core, skills, frontend, infra]
```

### 10. Verify locally (all must be green)
```
cd infra/terraform
terraform fmt -check -recursive        # exit 0
terraform init -backend=false          # downloads google provider, no creds
terraform validate                     # "Success! The configuration is valid."
```
Also sanity-check the workflow YAML parses:
`python -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))"`.

## Gotchas recap

- **Path is `infra/terraform/`, not `infra/`** — matches `.gitignore` (`infra/terraform/.terraform/`)
  and the spec. Root module goes in the `terraform/` subdir.
- **`validate` needs `init` first** — but `init -backend=false` (stateless, credential-free). Never
  run `plan`/`apply` in CI here; no secrets.
- **`.terraform.lock.hcl` is gitignored** — don't force-commit it; CI re-resolves providers each run.
  Fine for a resource-less skeleton; flag as a Sprint-2 reconsideration.
- **`terraform.tfvars.example` is the ONLY tfvars that may be committed** (`!*.tfvars.example` in
  `.gitignore`); keep it placeholder-only, no real project IDs/secrets.
- **Keep it minimal** — do NOT pull the 8 modules, §C4's full defaults, or `*.tftest.hcl` forward from
  Sprint 2; the roadmap flags Sprint 2 as the front-loaded infra sprint and S0.5 must not absorb it.
- **Pin the action SHA** (`hashicorp/setup-terraform@b9cd54a3c349d3f38e8881555d616ced269862dd` #
  v3.1.2) and set `terraform_wrapper: false` — the workflow is a security-sensitive merge gate; every
  other action in the file is SHA-pinned.
- **`ci-success` must list `infra`** or a real infra failure won't block the merge (the whole point of
  the aggregation gate).
