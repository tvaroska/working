# M1.8 — A2A edge (canonical, inbound)

**Milestone:** M1 — Bridge Core (local). **Depends on:** M1.4 (ledger), M1.6 (disposition), M1.3 (skill registry). **Blocks:** M1.9, M1.11 (dual-path), M1.13 (mock→real swap).

## Goal (what "done" means)

Stand up the **real Bridge's inbound A2A edge** in `bridge/` as an `a2a-sdk` JSON-RPC server that speaks the *exact same wire contract the mock already doubles*, so the eventual mock→real swap (M1.13) is a card-URL change only. The edge:

- serves a **dynamic Agent Card** built from the skill registry (M1.3, `LocalSkillRegistry.build_agent_card` already exists);
- exposes the canonical JSON-RPC surface — `message/send`, `message/stream`, `tasks/get`/`list`/`cancel`/`resubscribe` (all come free from `DefaultRequestHandler` + `create_jsonrpc_routes`, exactly as the mock gets them);
- runs a real collect round through bridge **core** (M1.6 disposition → M1.4 ledger projection over M1.2 aggregate tasks) rather than the mock's canned dispositions;
- maps disposition → A2A task status via a `_status_for` helper (`PENDING → INPUT_REQUIRED`, else `COMPLETED`);
- emits `ExchangeTurn{CollectionStatus}` as a JSON DataPart artifact with **`last_chunk=True`** (A12) and a **non-empty `status.message`** on every progress/park transition (A11);
- enforces the trust boundary **permissive-by-default** (A6): an unauthenticated / `None` caller is a no-op; per-party scoping only under `strict=True`.

This is the **inbound edge only**. Document intake routing (Path A vs Path B) is M1.11; requirements/advisory-completeness relay is M1.9; the fulfillment graph (M1.7) is already built and is NOT wired here (M1.8 depends on M1.6, not M1.7 — it runs disposition directly). Keep the scope at "the edge that accepts a `CollectRequest`, drives one core-computed collect round, and returns a contract-faithful `ExchangeTurn`."

## Key facts learned from the codebase (do not re-derive)

1. **The mock edge is the template.** `agents/src/agents/mock_bridge/app.py` (`create_app` factory + `build_agent_card`) and `executor.py` (`MockBridgeExecutor(AgentExecutor)`) show the exact a2a-sdk assembly: `DefaultRequestHandler(agent_executor, task_store, agent_card)` + `create_agent_card_routes(card)` + `create_jsonrpc_routes(handler, rpc_url="/")`, wrapped in a Starlette app with a lifespan that calls `handler.aclose()`. **Mirror this structure.** The real edge differs only in *where the ledger comes from* (bridge core, not canned fixtures) and in adding the trust boundary + `_status_for`.
2. **The executor emission sequence that the native consumer requires** (copy it precisely from `mock_bridge/executor.py`):
   - enqueue a `Task(id=context.task_id, context_id=context.context_id, status=TaskStatus(state=TASK_STATE_SUBMITTED))` **first** (a2a-sdk requires the Task object before any status-update events);
   - `updater = TaskUpdater(event_queue, context.task_id, context.context_id)`;
   - `await updater.start_work(message=new_text_message("<non-empty progress>"))` — non-empty message is load-bearing (A11: an empty proto Message is collapsed to `None` and silently dropped);
   - on progress emit `updater.update_status(TASK_STATE_WORKING, message=new_text_message("<non-empty>"))`;
   - artifact: `updater.add_artifact([new_data_part(turn.model_dump(mode="json"))], last_chunk=True)` — **`last_chunk=True` even for a partial (pre-park) collection** (A12: partial events are NOT persisted to the consumer's shared session, so the downstream gate never sees them unless flagged terminal);
   - terminal: `updater.complete()`; park: `updater.update_status(TASK_STATE_INPUT_REQUIRED, message=new_text_message("<non-empty park reason>"))` — **emit the collected-so-far artifact BEFORE parking**.
   - resume detection: a resume `message/send` carries the existing `task_id`, so `context.current_task` is populated and `.status.state == TASK_STATE_INPUT_REQUIRED`; branch on that to complete.
3. **Wire contract** (`agents/src/bridge_client/wire.py`, the contract M1.8 must satisfy — `bridge/` MUST NOT import it, replicate the shape):
   - **Inbound:** the `CollectRequest` arrives as a single JSON DataPart in one `Message` (`media_type="application/json"`, `role=ROLE_USER`), read with `a2a.helpers.proto_helpers.get_data_parts(message.parts)` → `CollectRequest.model_validate(datas[0])`.
   - **Outbound:** on completion the full `ExchangeTurn` is a single JSON DataPart in `task.artifacts[0]`; an empty `context_id` is backfilled from `task.context_id` (so always stamp `context_id` on the turn).
4. **Card is already dynamic.** `LocalSkillRegistry.build_agent_card(base_url=..., version=..., capabilities=...)` builds the card from process skills (advertises `address-proof`). Use it. **Set `capabilities=AgentCapabilities(streaming=True, push_notifications=False)`** — `streaming=True` is required so the native `RemoteA2aAgent` consumer receives progress `TaskStatusUpdateEvent`s (matches the mock).
5. **Ledger / aggregate projection is built (M1.2 + M1.4).** `bridge.aggregate.create_leg_task(context_id=, ordinal=, task_id=)` mints a leg task with the durable `bridge_ordinal` stamped; `bridge.ledger.stamp_ledger_entry(task, entry)` stamps a `LedgerEntry` onto `task.metadata`; `bridge.ledger.build_exchange_turn(context_id, tasks, outstanding=, terminal=)` folds the per-task entries into an ordinal-sorted `ExchangeTurn`. Use these — do NOT hand-assemble `CollectionStatus`.
6. **Disposition is built (M1.6).** `bridge.disposition.classify_document(doc_id, extraction, thresholds=) -> (LedgerEntry, DispositionResult)`. The `LedgerEntry` already carries the canonical issuer + disposition. `DispositionThresholds()` defaults to `(0.55, 0.85)`; the skill policy's thresholds come from `LocalSkillRegistry.get_skill("address-proof").policy` if you want to source them (M1.3), but the defaults match ADR-0002 — sourcing from policy is a nice-to-have, defaults are acceptable for M1.8.
7. **Extraction seam (fixture engine, M1.7 adapter).** `bridge.adapters.local.extraction.FixtureExtractionEngine().extract(FixtureDocument(fixture_id=...), None) -> Extraction`, loading from `wiki/evals/address/expected.json`. Fixture ids available: `gov-id-clean` (accepted/auto_approve), `bill-powerco-clean`, `bill-aquautil-clean` (accepted), `gov-id-expired`/`bill-aquautil-clear` (pending/hitl), `bill-aquautil-blurry` (rejected/resubmit), `passport-unsupported` (rejected/unsupported). Party in the evals is `jordan-lee`.
8. **Package boundaries (hard constraint):** `bridge/` **never imports `agents/`** (guarded by `bridge/tests/test_no_agents_import.py`), and `agents/` does **not** depend on `bridge` today (only on `contract`). So the M1.8 round-trip test **cannot** import both the real edge and the real `RemoteA2aAgent` consumer in one process without a new cross-package dep — and adding that dep is **M1.13's** job ("point the address agent at the real Bridge"). Therefore M1.8's round-trip is verified **at the wire level inside `bridge/tests`**, replicating the `wire.py` encoding (contract-faithful, no `agents` import). The deeper native-consumer round-trip is deferred to M1.13. State this explicitly in the test docstring.
9. **In-process HTTP for tests without uvicorn:** drive the Starlette edge app via `httpx.AsyncClient(transport=httpx.ASGITransport(app=app), base_url=...)`. `bridge/` already depends on `a2a-sdk[http-server,sql]` (brings Starlette) and `httpx` is transitively present via a2a-sdk/adk. Use the a2a-sdk client (`ClientFactory` + the card) OR hand-build JSON-RPC `message/send` bodies. Prefer the a2a-sdk client path (`a2a.client`) so the test exercises the real spec methods; fall back to raw JSON-RPC POSTs if the ClientFactory needs a live socket. (The mock's live tests use uvicorn via `LiveMockServer`; `bridge/` has no uvicorn dep — do NOT add one; use ASGITransport.)
10. **`_status_for` semantics:** the task line specifies `PENDING → INPUT_REQUIRED, else COMPLETED`. So `ACCEPTED` and `REJECTED` both map to `COMPLETED` (a rejected-terminal collection completes the task; the ledger carries the rejection). The exchange-level disposition for a multi-doc round is: `PENDING` if any entry is `PENDING` (or the collect plan has outstanding rounds), else `COMPLETED`.

### `bridge/src/bridge/edges/a2a/executor.py`
`BridgeExecutor(AgentExecutor)` — the real-Bridge collect executor. Mirror `MockBridgeExecutor` structure but drive the ledger through core.

`execute(self, context, event_queue)`:
1. **Trust boundary (A6):** derive the caller identity from `context` (the a2a-sdk `RequestContext` — check `context.call_context`/`ServerCallContext` for a party/user claim; if absent, caller is `None`). Call `authorize_leg(caller, request.party, strict=self._strict)` — permissive no-op when caller is `None`; raises only under `strict=True` on party mismatch. (See `trust.py`.)
2. **Resume branch:** if `context.current_task is not None and context.current_task.status.state == TASK_STATE_INPUT_REQUIRED` → run the next collect round for this context and complete/park accordingly (mirror the mock's resume branch).
3. **Parse the request:** `datas = get_data_parts(context.message.parts)`; `request = CollectRequest.model_validate(datas[0])`. Record `self.last_request_data = datas[0]` and `self.context_ids_seen.append(context.context_id)` for test introspection (parity with the mock).
4. **Aggregate:** per-context round counter (`self._rounds: dict[str, int]`). The exchange `context_id` is `context.context_id` (minted by the consumer/a2a-sdk; the edge continues it — do not re-mint). Keep a per-context list of leg tasks in memory (`self._tasks: dict[str, list[Task]]`) so `build_exchange_turn` can fold the whole exchange. (M1.8 keeps this in the executor; wiring it through the real `TaskStore.list` via `aggregate.tasks_for_context` is a later refinement — note it, don't block on it.)
5. **Drive one collect round** via `self._collect_plan`: it yields the fixture id(s) that "arrived" this round for `(request.skill, request.party, round_index)`. For each: `extraction = await engine.extract(FixtureDocument(fixture_id=fid), None)`; `entry, result = classify_document(fid, extraction)`; create a leg task `task = create_leg_task(context_id=context.context_id, ordinal=next_ordinal(existing), task_id=<fresh>)`; `stamp_ledger_entry(task, entry)`; append to `self._tasks[context_id]`.
6. **Compute terminality + outstanding** from the plan: `terminal = plan.is_terminal(round_index)`; `outstanding = plan.outstanding(round_index)` (advisory refs like `["utility-bill"]`; final completeness stays app-owned — do not compute `is_satisfied` here, that is the consumer's sense-B gate).
7. **Overall disposition** = `PENDING` if not terminal (more rounds outstanding) OR any entry disposition is `PENDING`, else the terminal disposition. `next_state = _status_for(overall_disposition)`.
8. **Emit:** `Task(SUBMITTED)` → `start_work(message=new_text_message("Collecting <skill>…"))` → `await asyncio.sleep(self._hold_seconds)` → optional `update_status(WORKING, message=...)` progress → build `turn = build_exchange_turn(context_id, self._tasks[context_id], outstanding=outstanding, terminal=terminal)` → `add_artifact([new_data_part(turn.model_dump(mode="json"))], last_chunk=True)` → if `next_state == INPUT_REQUIRED`: `update_status(TASK_STATE_INPUT_REQUIRED, message=new_text_message("Awaiting additional proof to proceed."))`; else `complete()`.
9. **`cancel(self, context, event_queue)`:** `TaskUpdater(...).cancel()` (mirror the mock).

Add a module-level `_status_for(disposition: Disposition) -> TaskState`:
```python
def _status_for(disposition: Disposition) -> TaskState:
    """Map an exchange-level disposition to the A2A task state (M1.8).
    PENDING → INPUT_REQUIRED (park, still collecting); ACCEPTED/REJECTED → COMPLETED."""
    if disposition == Disposition.PENDING:
        return TaskState.TASK_STATE_INPUT_REQUIRED
    return TaskState.TASK_STATE_COMPLETED
```

### `bridge/src/bridge/edges/a2a/plan.py`
`CollectPlan` — the small, injectable "what documents arrived this round" abstraction that lets the edge drive a real, core-computed collect without pulling in M1.7's fulfillment graph or M1.11's dual-path routing. Keep it deliberately minimal:

```python
@dataclass(frozen=True)
class CollectRound:
    fixture_ids: tuple[str, ...]
    terminal: bool
    outstanding: tuple[str, ...] = ()

@dataclass(frozen=True)
class CollectPlan:
    rounds: tuple[CollectRound, ...]
    def round_for(self, index: int) -> CollectRound: ...  # clamp to last
    def is_terminal(self, index: int) -> bool: ...
    def outstanding(self, index: int) -> tuple[str, ...]: ...
```
Provide named default plans that mirror the mock's scenarios (needed by M1.13 parity):
- `GOV_ID_INSTANT` — one round, `("gov-id-clean",)`, terminal.
- `TWO_BILLS_DISTINCT` — round 0 `("bill-powerco-clean",)` non-terminal outstanding `("utility-bill",)`; round 1 `("bill-aquautil-clean",)` terminal. (Distinct issuers → satisfies the app's sense-B rule.)
- `REJECT_RESUBMIT` — round 0 `("bill-aquautil-blurry",)` (rejected/resubmit) then a follow-up round with an accepted doc; keep it terminal-outcome-parity with the mock's `reject-resubmit` (A2: parity is terminal outcome, not ledger-identical — do NOT try to match the mock turn-by-turn). Note in a comment: a resubmission is handled *inside one Collect task* on the real Bridge (A12), so this plan is a modeling convenience for the edge test, not a claim about consumer round structure.
- Map a default plan by skill: `DEFAULT_PLANS = {"address-proof": GOV_ID_INSTANT}`; `create_app` uses `collect_plan or DEFAULT_PLANS.get(skill, GOV_ID_INSTANT)` (resolve per-request by `request.skill` inside the executor, since the app doesn't know the skill until a request arrives — simplest: executor holds the plan map + an override).

Rationale to record: M1.8 owns the *edge mechanism*, so the collect content is a fixture-backed stand-in. When M1.11 (dual-path) lands, the arrived-document source becomes real Path-A/Path-B intake feeding M1.7; `CollectPlan` is the seam that swap slots into. Do not over-build it.

## Gotchas / non-obvious decisions

- **Do not compute `is_satisfied` in the edge.** Completeness is the app's sense-B decision (consumer-side). The edge supplies `outstanding` (advisory) and a `terminal` flag from the collect plan; the final "done" belongs to the agent. M1.9 formalizes the advisory relay.
- **Do not wire M1.7 fulfillment or M1.11 dual-path.** M1.8 runs `classify_document` (M1.6) directly. The `CollectPlan` fixture stand-in is the intentional seam where M1.11's real intake slots in later.
- **a2a-sdk types are protobuf** (1.1.x): build with kwargs, read with `.field`/`get_data_parts`/`get_function_*`; never `.model_dump()` on A2A types. `task.metadata` is a `Struct` (numeric round-trips as float — `aggregate.ordinal_of` already casts). Use `new_text_message` / `new_data_part` from `a2a.helpers.proto_helpers`.
- **`context_id` continuity:** the consumer threads the same `context_id` across rounds (its interceptor). The edge continues it — never re-mint on a continued/resume message. Always stamp `context_id` on the emitted `ExchangeTurn` (empty → consumer backfills from `task.context_id`, but stamping is cleaner).
- **`hold_seconds` default 0.0** for the real edge (the mock's ~10s hold was an M0 async-path demonstrator); keep it injectable so a test can still assert the WORKING-before-COMPLETED ordering.
- **Package layering:** `bridge.edges.*` may import `bridge.seams`, `bridge.adapters`, and core (`disposition`/`ledger`/`aggregate`/`skills`); core must not import edges. Keep the edge out of `bridge/__init__.py`.
